# 数据迁移与备份（1.0.0）

本文适用于 1.0.0；0.9.3 的入口和文件格式见旧版说明。

## 从旧版本升级

运行环境需要 Node 22.13 或更高版本，并能使用内置 SQLite。通常由桌宠安装包提供；如果新版提示环境不支持，请升级桌宠的运行环境。扩展不会在不支持时创建一本新空信册冒充迁移成功。

第一次启动新版时，固定范围内的旧本机数据会先备份，再迁入 `bottle-local.sqlite`。正文、回信、小纸条、已读和共读记录、失效未寄稿、星标及原有授权、草稿版本、真实收信时间、身份、提醒状态、主题、笔迹绑定与自定义字体/背景都会保留。迁移本身不会发信，也不会额外读取信件给桌宠。

确认写入并校验成功后，旧文件停止使用；源文件校验失败、损坏或写入失败时中止，原件仍在。重复启动不会反复导入、重置身份或多算信件。迁移前备份保存原始文件字节，供自己恢复和排查，**可能包含本机身份及原草稿寄送状态，请勿转发**；通过页面导入它时只提取可恢复的历史，不恢复身份、自动寄送或授权。

恢复迁移备份时，旧文件中仅保存在手中、尚未进入历史列表的原信也会收入信册；已有同编号原信时不重复添加。恢复不会重新占住海上的信件或恢复阅读授权。JSON 虽能解析但列表/记录结构损坏、编号重复时，同样会拒绝迁移并保留原文件。

「数据迁移与备份」卡片显示当前存储方式和迁移结果，也列出迁移前与覆盖前备份，可逐份下载、删除。扩展不会自动替你删除这些保留备份。清空当前信册不会替你删除已经下载到其他地方的副本；如果本机还留有备份，会在清理结果中提示。

## 在哪里操作

桌宠设置 → 漂流瓶 →「信箱」页签 → 底部「数据迁移与备份」。这里集中提供导出、导入比较、保留备份的下载和删除。

独立信箱底部不再直接导入或导出，只提示上述入口，并提供本设备素材的收集与应用。手机仍可以正常看信、确认寄出；整库管理放在扩展页，避免阅读时误覆盖。

## 选择带走的内容

| 类别 | 包含什么 |
| --- | --- |
| 信件与回信 | 寄出、收到的普通信及回信，正文、标题、实际时间、共读次数、随信装饰和失效未寄表达 |
| 小纸条 | 收到和寄出的原文、已读状态；恢复不播报，不自动补寄 |
| 系统来信 | 邮局/群岛来信及其已有署名、装饰和实际收信时间 |
| 未寄草稿 | 新信稿和回信稿的正文、标题、装饰；恢复后必须重新处理，不恢复定时寄送资格 |
| 星标 | 收藏标记和时间；导入不授予桌宠记忆权限 |
| 自定义涂鸦 | 用户添加/修改的素材；信本身已有的装饰始终跟随对应信件 |
| 自定义字体与笔迹 | 自选字体文件、匿名署名与笔迹的绑定；不重复打包可重新下载的公共云字库 |
| 自定义音效 | 自己添加的音效、当前选中的本机文件，以及明确收集过的浏览器自选音效；不重复备份内置原始音效 |
| 主题与背景 | 本扩展主题色、明暗、自定义背景和最近一次宿主颜色快照；不读取宿主私有主题文件 |
| 阅读与设备偏好 | 明确收集过的各设备字号、工具停靠、声音选择、音量与淡出等偏好 |

可以全选，也可分开备份。只选系统信不会顺便带出普通信正文。星标或纸条可以单独保存，它们引用的原信未包含时，恢复后仍按原有缺少历史的提示展示。

新的 `.bottle-backup` 是压缩文件，**没有加密**；里面有正文和自己的素材，不要随意转发。压缩文件最大 128 MiB，展开最大 256 MiB；单字体最大 32 MiB、背景 8 MiB、自选音效 10 MiB。资料较多时分开选择类别导出。浏览器下载成功后请自己保管文件。

通用导出不包含海边/配对/Bridge 凭证、删除凭据或模型授权；宿主配置继续由框架管理，不会把整个桌宠部署配置或聊天打进备份。迁移前原始备份的范围与通用导出不同，见上文提醒。

## 导入之前先比较

1. 选择旧 v1/v2 JSON 信册，或新版 `.bottle-backup`。页面会先上传并检查，不立即改当前信册。
2. 看「本机现有」和「备份带来」的数量：寄出、收到、回信、系统来信和合计。这里不展示正文；合计是这几类记录的总数，原信和收到的回信分别计算。
3. 选择保留本机（取消导入）、合并（已有内容优先），或使用备份替换它包含的类别。没有包含的类别不会被替换。
4. 替换默认先备份将被替换的数据。可以取消这个勾选；保留勾选时，备份失败就不会继续覆盖。完成后可在卡片下载这份旧数据。

如果比较期间又收到了信或修改了本机数据，需要重新比较。预览十分钟失效，取消预览不改数据；重复点同一次确认不会重复导入。损坏、不支持的文件会被拒绝。

正在处理的原信、已确认定时稿、待确认寄送纸条及对应往来会保留。当前已有草稿时，不能用「替换草稿」顺便撤销它，应先自己处理原稿，或选合并保留本机稿。导入的回信不重新占住海上的原信：能挂在原往来下就作为失效未寄表达保存，否则只留为不能投递的草稿。旧发送确认、定时凭据、模型阅读/记忆授权不会从备份复活。

替换素材库时，现有信件、未替换主题或保留设备偏好仍在使用的素材会留下；同编号的在用素材不会被另一份图案悄悄改画。这样只换素材库时，不会顺手破坏仍保留的信件排版。

## 手机或浏览器自己的音效

每台浏览器的自选文件原本只在该浏览器里。电脑无法隔空读取手机的本地文件，因此需要在那台设备的信箱底部展开「数据迁移与备份」，点击「收集本设备素材」。

点击后，自选音效、字号和阅读工具位置等才会传给本扩展所在电脑，并收入 SQLite；不会上传中央海边服务器。只是选择音效或打开网页不会自动上传。对外信箱仍需要原有配对和同源验证。

恢复了包含这些内容的备份后，在新设备信箱中点「查看可恢复的设备偏好」，选一份，再点「用于本设备」。不会覆盖其他设备的独立选择。声音仍需自己点击「启用声音」才能播放，不会因为恢复备份突然响铃。

数据卡片也可将已恢复的自定义音效用于桌面来信或回信。当前配置引用的本机音效文件只读收集，不会替你删除外部原文件。Windows 播放时可能生成短暂的本机音频文件，权威副本仍在 SQLite，停止扩展时清理。

## 保存边界

信件、纸条、草稿与设置转入 SQL；内置 SVG、默认音效、许可与云字库元数据仍是安装资源。框架 secret/配置继续使用公开接口。Windows 卡片与 Bridge 发现文件是临时进程通信，并非另一套信册。

传输临时文件在取消、完成、预览/下载到期或停止扩展时清理；进程意外退出残留超过一天的已知临时文件，在后续启动时清理。迁移前/覆盖前的保留备份不会跟随临时文件清理。

如果想退回 0.9.3，旧程序不能直接读 SQLite。请先保管现有备份和数据库，勿直接让旧程序覆盖当前数据；回退资料需要转换为旧版兼容的信册格式，并单独保管自定义素材。新增的分类压缩备份应使用 1.0.0 或更新客户端恢复。
