# 阶段 C、E 实现范围

依据 2026-11-12 操作手册，延续 A/B/D 修复后的数据与发送策略。

- C：网页和原生卡片携带真实草稿 ID/revision/kind；与模型工具复用 World 确认、发送锁、修改锁和 generation 检查。等待自动任务后重新校验；异步重写的模型结果也校验原稿是否仍为请求时的版本。保留旧本机路由的兼容行为，不把它描述为权限沙盒。
- E：独立人工 opt-in、独立 Bearer 凭证、实际本机端口发现；仅状态、投入待审新信和打捞元信息。正文校验与模型起草共用业务方法，不用 HTTP 绕回网页，不提供 Agent 寄出或配置接口。外部来源持久标注，不伪称人工审批；LAN 不暴露 Bridge。
- 按后续确认追加 Controller：另一个默认关闭的开关和独立密钥，提供指定草稿预览/确认寄出/重写/放弃，指定信回信/一起看/归还/收好；普通 Agent 无这些操作权。新回信手动确认，不开启定时寄出，不依赖无头开关。
- F：只调整确认负载和外部草稿来源提示，不改信箱布局、样式、分区、字体或原有操作。教程和碎碎念仅新增在 `E:/BottleWeb/guide` 与 `E:/BottleWeb/notes`；原有网页文件不改。

回归集中于 `tests/bridge.test.ts`、`tests/draft-confirmation.test.ts` 及现有 headless / reply-auto-send / page / cards / lan 用例。教程是本地静态源码，发布路由、推送、线上配置与服务重启不包含在实现动作中。
