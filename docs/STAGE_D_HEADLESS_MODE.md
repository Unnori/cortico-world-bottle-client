# Stage D 无头模式

默认关闭，由人显式启用。工具每次执行检查实时开关、生命周期及读信意图，不验证通讯平台身份。

0.9.1 修正注册方式：宿主只在重建前缀时重取工具表，因此工具声明固定注册，不能按热开关删减。关闭时所有无头 handler 仍立即拒绝读/发；开启后同一会话可直接使用发送、草稿查看和既有 bottle_reply，不以发现工具为授权。真实 Core 会话回归在 tests/headless-session.test.ts，覆盖从关闭启动、热开启、自动共读/起草、当轮禁寄、后续列稿/看稿/确认发送、再次关闭。

- 无头下桌宠打捞会排队 `bottle.headless-reading` 外部事件，先分享完整原文与感想，可为当前信起草一份 manual 回信；本轮禁止寄出/放弃，等人后续明确确认。投递前重验开关、会话、目标和正文；关闭、归还、过期、停止会使排队内容失效。人工/Bridge 打捞不自动递正文。
- 普通逐封读信与起草回信仍分开；人另行要求回信时，`bottle_reply` 默认使用当前持信，可省略 `letterId`。也可显式传 `held` 或当前信编号，不能传聊天消息编号；错目标会拒绝。已有只读/小纸条授权不能借此变为回信授权。自动共读事件已绑定当前信，不必传编号。
- 无头新回信策略为 manual，不调用服务端待寄保护，沿用原信有效期；过期不能寄出。
- 桌面 delayed 稿保留原倒计时，重写不延期，开关变化不更改草稿策略。
- 草稿有持久 draftId 和单调 revision；正文、标题、装饰修改使旧确认失效。槽名 letter/reply 不能用于发送。
- 查看/发送/重写/放弃使用确切 ID，发送和重写/放弃须当前版本。网页、工具复用 World 发送锁和业务方法。
- `bottle_manage_letter` 按明确 ID 归还或收好，沿用现有服务端规则。
- 网络结果未知提示待确认，不自动重发新信。
- `bottle_mailbox` 的无头目录只含元信息；读指定已寄往来包含收到的回信。

主回归位于 tests/headless.test.ts，类型检查与完整测试结果以本次实际运行记录为准。真实部署、生产脚本安装与开启开关由人决定，不由安装/迁移替人开启。
