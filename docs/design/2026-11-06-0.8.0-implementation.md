# 0.8.0 最新确认口径（2026-11-06）

本文件按用户最新五项修订与“人点击确认寄出”答复更新，覆盖此前 B 给 A、禁止后台唤醒和星笺只收藏的中间方案。信/回信正文不在服务端落盘，本机信册与用户明文导出例外；不改 Core。

## 当前行为

- A 寄信 -> B 回信 -> A 收到后邀请自己的 Coo 留纸条给 B。只有明确 note 邀请轮次可以 bottle_note 起草 1—40 字，工具不接编号。人只能确认寄出或放弃；POST /note 不接受正文，发送只读取 World 内的 Coo 草稿。草稿仅内存，寄出/放弃/删除对应往来/停止 World 或一小时后清理。
- 发出纸条消费一次打捞机会；回信与纸条独立，纸条失败不影响已有回信。服务端 db v3 保存纸条正文；GET 只标送达，浏览器可见后 ACK 真删，七天到期清理，无正文重试凭据同样七天删除。生成端纸条文字在自己的模型输出中，收到的纸条不进收件端事件/工具/env；不承诺生成端零模型痕迹。
- 共读第一屏一起读/扔回海里；成功共读后显示“桌宠名已经读过了”，第二屏写回信/扔回海里。共读不修改 replyWindowUntil/windowUntil，沿用捞起时的回海期限。只有明确写回信且有效草稿保存后，才申请服务端无正文待寄保护并开始两小时自动寄出计时；sweep 遇待寄保护跳过回海，即使原期限先到也不丢信。重启恢复、网络重试沿用同一草稿编号和服务端时间；回信编号稳定派生，丢响应不重复发送或计费。显式放弃/归还解除保护，readAt 不传给下一位。旧服务器缺少 reply_draft_hold 能力时不请求新接口，共读本机授权、回信仍手动寄出。Core 缓存工具表，handler 必须核验 read/reply/note 意图。
- 捞信工具回执包含实际署名、已有标题和额度；无题省略标题，不取正文首行，不作联系方式摘要替换。全文仍按点击或星笺授权交付。
- 原有自动写信邀请、自动打捞邀请、待办提醒、到信/被捡起/海啸/系统邮件事件恢复，沿用旧额度/间隔/暂停/有限重试，后台事件不夹带新来信正文。公告保持网页专用。
- 恢复扩展管理的长期星笺库：总开关与逐封授权共同控制，星标成功后弹窗询问；只收藏/关闭不递正文，确认开启总开关并只授权当前通信。投递时重验；撤回、取消星标、关闭总开关使排队正文失效。不修改核心 Memory，历史会话/摘要不可追回。
- 信册 JSON 导出/合并导入在独立网页顶部及 World 信箱面板底部折叠入口共享实现。仅导出信册记录、时间、星标，不包含凭据、纸条、草稿/手持任务状态、模型授权或外观资源。完整验证，类型/id 去重，本机优先；导入不唤醒。
- 海啸重投保留：原信不复活，稳定新 id 幂等，用一次打捞机会；可由作者点击提交本机原文，缺失则明确失败。

## 新持久字段与删除

| 字段/数据 | 保存地点 | 什么时候删除 |
|---|---|---|
| notes: id, letterId, fromHash, toHash, body, createdAt, deliverAt, expiresAt | 服务端 db v3 | 收件人展示后 ack 删除整条，或创建七天到期；请求/load 即时过滤，运行中每分钟清盘 |
| noteReceipts: id, letterId, fromHash, expiresAt（无正文） | 服务端 db v3 | 创建七天到期删除，用于这段时间内网络重试/ack 后重试不重复扣费；不保留永久收条历史 |
| replyDraftKey/replyDraftDueAt（不含正文） | 服务端既有 letters 行 | 寄出、明确回海/沉底/归档或取消草稿时删除；服务端重启仍保留待寄保护，供本机补寄。到期时间表示应寄出时刻，不代表取消保护时刻；本机永久离线或丢失草稿需人工放弃/归还才能解除 |
| autoSendKey/autoSendAt | 本机既有回信草稿槽 | 草稿寄出、放弃、删除对应记录或清空本机存储时删除；删除前须确认取消服务端保护，网络失败保留并提示。World 停止保留，重新启动沿用原到期时间 |
| LocalHeld.readAt | 本机既有信册的 held 槽 | 寄出、收好、扔回、删除、清空 held 时删除；不上传或传给下一位收信人 |
| 导入信件与星标 | 本机既有信册/星标文件 | 使用原有单封删除或清空路径，不另存导入历史；正文不进入服务器持久化 |
| 明文导出 JSON | 用户选择的下载位置 | 由用户持有和删除，界面/文件名明确风险，不上传 |
| 页面收到纸条的 DOM | 仅当前浏览器内存 | pagehide 清空；接收纸条到其 expiresAt 计时清空，不写 localStorage/IndexedDB |

长期服务端备份排除 notes 正文，避免把 ack/TTL 已删除的纸条留在三十天备份中。Db.save 只为 notes 写正文，其余正文始终置空、topic 不写盘；失败时新功能不报告成功、不扣费。
数据库原子写入的同名 .tmp 文件在失败时清理；进程中断留下的 .tmp 在下次正常打开数据库时清理，不被当作持久副本保留。readRaw 运维只读路径不改变文件。

## 追加计时验收

共读不调用服务端 /read；保留该端点兼容已有客户端，但不延长或清空回海期限。新增 POST /reply/draft 只收信件 id 与草稿幂等键/取消标记，不收正文。服务器只有在声明 reply_draft_hold 后客户端才申请保护。自动寄出由 World 计时器执行，不增加模型寄信工具。默认每秒检查，到期网络失败每分钟重试。重写只有新稿有效时才替换旧稿，沿用同一凭据与原倒计时，不重新延长；旧稿到期优先寄出，不因正在生成新稿无限延后。

最终本地验证（2026-11-06）：pnpm typecheck 通过；pnpm test 为 51 文件 / 835 用例全通过，包含 24 个回信自动寄出测试；真实 Core 配假 Provider 的隔离测试、临时 HTTP 服务的浏览器测试、框架 describe/check 均通过。部署包实际 Node HTTP 验证了待寄保护跨重启、回海检查优先避让、重复提交不重复扣费，信/回信正文仍不落服务端磁盘。完整日志在工作区 scratch/bottle-080-auto-reply-full-final.log，部署包报告在 scratch/bottle-deploy12-verification.json。所有测试使用合成信件；实际运行实例未自动重启，公网服务未部署。


### 小纸条重写与附信展示（11 月 6 日修订）

只允许桌宠在人的明确邀请下重写，小纸条不提供人工输入或编辑接口。重写成功才替换草稿，失败保留原稿，重写不延长最初一小时有效期；寄出时才扣打捞额度。放弃同时撤销仍在执行的纸条授权，避免草稿重新出现。收到的小纸条按 letterId 附在原往来下方，待寄草稿附在收到的回信下方；页面重绘复用节点，展开且可见才 ACK，页面离开或 TTL 到期清除正文。缺失本机原信时保留对应信件占位以便阅读纸条，不创建独立纸条列表。没有新增持久化字段。


### 小纸条自动到信与一起看（后续修订，覆盖只在人端展示）

用户明确要求收到纸条自动唤醒桌宠并递正文，请桌宠转告人；此时仅纸条正文自动授权，原信和原回信不随后台事件递出。复用信箱刷新读取 /notes，不加新定时器。纸条先写入本机 bottle-notes.json 再向服务端 ACK；本机缓存、readAt、无正文删除凭据均沿用原纸条创建七天期限，删对应往来或清空信册立即清正文。删除凭据防 ACK 失败后重复恢复，原期限到期删。缓存不进星笺记忆和信册导出。延迟事件以外部内容投递，实际送达后标已读，未送达保持未读；重启不重复通知已读纸条，删除/过期/World 停止时撤销排队内容。人点击「一起看」单次附上纸条、原信、原回信，只读和谈感想，不允许自动起草回信或纸条。网页只显示未读/已读两态，仍附在对应往来后。


### 本机纸条永久留存（最新修订）

用户澄清「用后即删 / 七天期限」只约束服务器，不约束本机信册。已收到的纸条正文与 readAt 永久保存于本机 bottle-notes.json，按 letterId 附在对应往来后；仅人删除对应往来或清空信册时删除。旧文件中的 expiresAt 仅为服务端配送期限，升级加载时即使该期限已过仍保留本机正文与已读状态。网页也不按 expiresAt 隐藏或删除纸条。仅未收到的过期远程纸条不能新领；无正文删除凭据仍按服务端原期限清理。草稿仍只在 World 内存保留一小时，不受本次修改影响。服务端代码与 deploy12 包不变。
