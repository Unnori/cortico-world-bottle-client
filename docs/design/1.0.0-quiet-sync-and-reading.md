# 1.0.0：安静收信、合并同步与本地查信

2026-11-16。按本轮九项要求实施 1—8；第 9 项只给存储建议，暂不迁移客户端。全部本地保存，不提交、部署、重启实际桌宠，不修改 E:/BottleWeb。

## 确定的行为与实现选择

- 系统来信提醒默认开启；关闭后仍在信册接收系统信，停止通知及自动阅读。延迟事件投递前重验开关。无头转述正文独立开关默认关闭，开启后自动阅读可同时转述，显式问原文仍可回答。
- 默认 10 分钟同步一次，可设 1—60 分钟；启动时同步一次。独立网页和设置面板只读本地，不绕过该节奏。真实寄送/打捞等动作仍即时查询所需数据。
- 新服务端 POST /sync 一次返回额度/公告、回信、纸条和本次系统信完整内容。普通 GET 仍只读，不以 GET 偷偷领取系统信。纸条先保存本地，ACK 随下一次同步发送；保留旧 API，旧客户端继续可用。新客户端遇到汇总接口明确不支持时使用旧接口；网络失败不盲目回退或重试领取。
- 系统信投送前要有此前一小时内成功鉴权的查询；本次领取不能给自身创造在线证据。首次查询建立在线记录，之后才可能领取。实际两次投送至少间隔 60 分钟（用户已选），由服务端可调；时间存账号元数据，不因跨天、重启、刷新 token 或多端请求重置。
- 本机实际接收成功时记录 receivedAt；同一原信重新捞到时记录此次实际收信时间。回信生成时间与收信时间分开；旧数据没有新字段时不补猜。网页使用低强调的分钟时间，不写入桌宠读信正文。系统信响应丢失时汇总接口可再次返回同一待确认信，客户端按 ID 去重并在保存后随下次同步确认。
- 被捡起、收到回信等延迟通知只把相对时间明确绑定到寄出等已知动作；绝不把查询到状态的时刻说成事件发生时刻。
- 信册增加本地检索，按标题、正文或署名匹配，不上传关键词；沿用分类与折叠，使用“在信里找一找”等文案，不大改页面。
- 所有草稿入口共用状态：待确认、已安排定时寄出、补寄中、已失效。只统一状态，不改变 manual/delayed 策略和人的确认边界。
- 待办提醒单独声明 piggyback；写信与打捞主动邀请仍 flush。提醒排队不占一次投递、不开始下次间隔，实际 delivered 后才计数与安排；投递前重算待办，忽略或明确拒绝仍可安静延后/暂停，不催促或归罪。

## 取舍及边界

仅将三个独立轮询改成十分钟仍有多次往返，故新增汇总接口；新旧客户端和服务端交叉兼容，原接口不删除。聚合领取有副作用，因此用 POST。未确认投递不标成功、不自动重复寄信。

不借本轮重构本地存储，也不统一寄送策略；避免功能修复与数据迁移混在一起。新增元数据随账号或信件/草稿/对应往来删除，临时投递 token 仅内存。服务端仍不持久普通信件正文。

## 验证范围

开关热切换与已排队事件失效；汇总单请求/节流/旧端回退/ACK 与重复响应；系统信首次在线、60 分钟、午夜、重启、同账号多端；旧数据无时间及时间显示；本地检索与各草稿入口状态；延迟提醒实际投递计时、无主动唤醒、主动邀请仍正常。单元、真实 HTTP、隔离浏览器/原生卡片；不访问真实用户聊天/信件或部署代码。

## 审查后的边界补充

系统信 pending ID/投送时间归账号所有，不再次扣次数；ACK 验证该账号已领取，撤下种子或七天未确认后在下次同步清理。首次查询不能自我证明在线；旧查询入口为 GET /quota、/mailbox、/notes。原 lastSeenAt 仍只供天级统计。

排队待办消失会取消，符合资格的显式邀请可替换陈旧提醒。相对寄出时间在真正 render 时重算。关闭系统提醒会使已排队通知失效，重新开启也不补播旧通知。

精确在线时间属于必要变动，旧客户端查询可能提交一个账号元数据行；不再全量重写，也不能沿用旧报告将其说成所有空轮询都零事务。
