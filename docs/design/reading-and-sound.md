# 阅读记录、通知音效与远端操作

本次沿用现有信册、World 配置页和共用 HTTP 路由，不修改宿主或中央服务端。

- 阅读次数随 `received`、`replies` 保存，老数据默认 0，非法数字归零。成功将正文排入 `pushEvent` 才累加；这表示成功递交，不声称模型已完成阅读。失败、并发重复提交不累加，仅展开正文不计数。
- 点击「回信」也会递交正文，因此计入次数；读来信、读回信分别计数。一起读回信会带原信作为上下文，但仅增加回信计数；`sent` 不计数、不展示阅读标记，加载时忽略旧版本误存的计数，只保留信件状态。计数只存在信册，不上传服务端。
- Windows 在新捞到的来信卡片、收到回信的卡片首次渲染时播放，草稿和等待卡片静音。`CardHost` 传 JSON 本机路径，独立 PowerShell MediaPlayer 负责播放，25ms 更新末尾线性淡出；随卡片关闭清理。默认来信为 incoming/New_notifications_1.wav、回信为 reply/New_notifications_3.wav，单文件最多 10MB、播放最长 30 秒，读取失败不阻塞卡片。
- 网页声音作为独立脚本加载，逐设备 localStorage 设置 + IndexedDB File。首次快照只建基线，之后按来信/回信及信件 ID 去重；持久存储被禁用时退回内存去重。浏览器音频需点击启用；旧信和离线期间积攒的信不补播。音量和 fade 由 Web Audio GainNode 调整。回环原生卡片模式避免网页与原生双响。
- `/sounds` 与 `/sounds/:id` 只枚举/读取包内音频；真实路径须在包目录内。桌面本机文件不开放给网页，对外监听的音效路由照常要求配对。

## 远端来源贯穿异步操作

只在卡片生成时按用户设备判断、或短暂设置一个全局“静音”变量，都无法覆盖排队后的模型工具调用，而且会误静音无关通知。采用任务携带来源：对外监听的 `pageHandler` 固定将操作 surface 设为 `remote`，不信任请求头；回环维持原来的 page/card。

打捞直接携带来源；桌宠邀请的来源写入具体 WakeTask 并随有限重试保留；人工邀请及重写用待处理请求保存；回信来源写入当前授权。工具成功时先读取对应来源，再完成/清除任务，仅抑制这次操作产生的卡片。失败、回合结束、超时和重启沿用原有任务清理。远端的人工写信等待最多沿用读信授权的 10 分钟窗口，以覆盖较慢的模型响应。

打开远端页面本身不全局关闭桌面通知；电脑自主行动及独立后台回信仍正常提醒。远端配对仅改变操作入口，正文仍须用户显式授权才能交给模型。

## 验证边界

内存服务端/假宿主验证读信递交、持久化、失败与并发，以及远端同步/异步操作不触发卡片；假音频上下文验证网页基线、去重、分类与淡出；Windows 只运行 PowerShell 解析和纯淡出计算，不自动弹窗或播放实际声音。独立浏览器页面验证 3 套主题 × 明暗 × 桌面/窄屏，以及真实 IndexedDB 文件保存与刷新后恢复。真实声卡效果与实际手机浏览器仍需人工试听。


2026-11-02 验证结果：全套 33 个测试文件、470 项测试通过，World 与 WebUI 类型检查、页面构建通过；最终手机摘要布局调整后追加 46 项页面回归通过。隔离浏览器完成 12 组主题/明暗/尺寸检查，并验证真实 IndexedDB 文件在刷新后恢复。运行中的 17788 宿主资源摘要与本地构建一致，新开真实宿主页后信箱入口、邀请设置、扫码卡片均可见；未点击配对或读取真实信件，验证页已关闭。这些宿主检查不代表新 World 逻辑已在运行进程重新加载，未自动重启桌宠。


## 音效目录隔离与默认值修正

2026-11-02：根目录直接音频标记 shared，在来信和回信选项中共同显示；incoming/ 与 reply/ 的直接音频仅出现在所属列表，不递归。桌面配置动态选项、卡片播放校验与网页下拉采用同一分类规则，根目录文件 ID 不带前缀。旧内置 default.wav 只迁移为各自的 New_notifications_1 / New_notifications_3；桌面自选其他文件不变，网页旧的跨目录或缺失选项退回对应默认。默认常量只在 sound.ts 声明，网页 HTML 与脚本从服务端模板注入，避免默认值再次不一致。


本次验证：全套 33 个文件、485 项测试通过，World/WebUI 类型检查通过；默认 WAV 由真实浏览器离线音频上下文解码成功（未连接扬声器），来信/回信分类与根目录通用音效的菜单检查通过，12 组信箱主题/尺寸布局及本机音效 IndexedDB 刷新恢复检查通过。原先缺失 default.wav 导致的 3 项失败已随新默认值修复。未重启实际桌宠或发布扩展，实际 Windows 扬声器与手机播放仍须人工试听。
