# 回信草稿保护到期回收（0.9.0）

旧源码和旧服务端包均存在问题：sweep 只判断 replyDraftKey 是否存在，未判断 replyDraftDueAt，过期保护永久阻止回海。包内服务端版本也误留为 0.8.0。

修复后两小时自动寄送时点不变，另有固定 24 小时的有限补寄保护，供断网、回执丢失、重启后补寄使用。到期或标记/期限无效先删保护，原回海窗口已到则释放；原窗口仍有效则继续普通持有。旧 null 窗口不能延续失效保护，正文缺失则归档为空信。清理在每次 API 请求入口执行，包括 /health，不依赖持有人上线。相同 key 重试保持原时点，不同 key 不能覆盖现有保护。过时补寄的明确失效优先于额度错误返回。

客户端收到明确失效时停止已确认稿补寄，清 held，保留正文为 manual/sendFailure=expired，并递增版本作废旧确认。它可查看/放弃，不可寄出/重写；网络失败不作此判断，仍按幂等凭据重试。失效状态随草稿写入 bottle-draft.json，重启保留，放弃/删除对应往来/清空时与草稿一起删除。页面只调整既有提示与按钮，卡片沿用现有结构。

修复同步到独立服务端与客户端仓内服务端副本。两端 package.json 均为 0.9.0，打包脚本强制版本一致，服务端包改用 bottle-server-0.9.0.tgz。旧包移入部署材料的 superseded/before-expiry-fix，并标明请勿部署。

验证：先运行新增回归，旧代码 12 项中 11 项失败；修复后通过。客户端全量 68 文件/1110 项通过，最后的失效优先级调整另跑 100 项相关回归通过；独立服务端最终全量 15 文件/197 项通过。TypeScript（客户端/网页/服务端）、框架装载与 Edge 页面验证通过；页面确认未寄原文保留且只提供放弃。实际执行解包后的服务端源码，复现 11-08 捞取、窗口晚 80 小时/草稿晚 102 小时，确认正文仍在、另一个账号可捞、旧持有人不能补寄。两包均核验实际 manifest 与源码字节、校验和。

交付证据：artifacts/validation/bottle-090-expiry-fix-20261113/verification.json，以及 artifacts/deployment/bottle-0.9.0-20261113/。本次没有部署、重启线上，也未修改实际报告的信件；源码包修复不代表现有旧进程已更新。
