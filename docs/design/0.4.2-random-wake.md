# 0.4.2 随机邀请与公告分流

> 本设计已并入 0.5.0（2026-11-02）；下文的 0.4.2 与“不发布”为设计时的版本编号和阶段安排。

按本次需求实现，暂不发布。所有改动限于漂流瓶扩展，不改宿主、服务端或正在运行的部署。

## 决策

直接定时调用写信/打捞工具会夺走 Bot 的选择；每次定时只推一句话则无法判断本轮是否处理。因此采用持久化 World 任务 + 延迟唤醒 + 显式选择工具。信件发送仍只由人确认。

每分钟检查条件，并合并需要的额度刷新；首次及普通下一次在 2—4 小时后随机安排，每类每天最多 3 次，跨类型普通邀请间隔至少 1 小时。检查本地额度，写信要求 bottles_left > 1；打捞同时要求 catches_left > 1 和 replies_left > 1，缺失的额度按不符合处理。有信稿、回信稿或待处理来信时改为提醒；读信授权、人工请求、寄送或另一份任务时不另起邀请。运行阶段忙碌时不排新任务。

## 任务

bottle-wake.json 原子保存唯一任务 ID、动作、投递阶段、尝试次数、下次时间、当日计数、暂停标记和最近 24 条结果。任务 ID 不放在事件文案或工具参数中。

queued → rendered → delivered → completed / deferred / declined / paused；一轮没有结果记 uncompleted，30—60 分钟后只重试一次，沿用同一 ID；第二次仍未完成记 failed，当天停止该动作。重启将旧任务记 interrupted 并延后，不立即补发。工具验证失败不算成功；打捞已实际检查但空海也算处理完成，不重复催捞。

no_idea / not_now 是 Bot 的自主延后；user_declined 仅用于人的明确拒绝，停止当天同类邀请；user_paused 持续到在信箱页签恢复。配置 randomWake 可关闭所有自动邀请。

## 暂停边界

当前 WorldHost 不暴露全局暂停查询，不读取 Core 私有状态。使用 pushDeferred + flush；Core 暂停时不会渲染或投递事件，也不消耗邀请计数。仅保留一份延迟项，恢复投递时重新检查条件。跨日过期项丢弃，重新随机安排。onEventsSettled 只结算匹配的任务，onTurnEnded 只处理已经投递的邀请；onRunPhase 只记录忙闲状态。

## 播报与公告

拾信首次播报标记保存在每封 SentLetter 的 pickedNoticed 字段，先落盘再投递，偏向不重复播报。旧信册缺字段兼容；升级前已播过但没有标记的历史无法追溯。

去掉 bottle.announcement 事件及其后台播报、已读去重状态。网页可见时每分钟最多请求一次本机 /announcement，由扩展在这个请求内读取服务端现有 /quota 的公告字段，不更新 World 状态、不触发播报；普通 quota 刷新忽略该字段。无需新增服务端接口。页面使用 textContent 显示，保留 alarm 的样式。


## 行动主体、提醒与设置补齐（2026-11-01）

- 新增 remind 通道，沿用唯一任务、检查、投递、每日上限、间隔和暂停状态；有 held/letterDraft/replyDraft 时取代写信/打捞邀请。提醒仅有计数，不读取信件或草稿。投递后的这一轮可明确延后；正常轮次结束记完成，不因没调用工具重试。
- 每个通道新增 intervalHours（缺省 2），随机延迟为 min(24, intervalHours × [1,2]) 小时，范围限制 2—24；旧 v1 状态自动补 remind 通道，不丢旧暂停。
- 网页默认 bot：按钮创建 manual 任务并立即 pushDeferred，仍由 Bot 决定。手动点击不要求保留最后一次额度，条件为机会 >0；尊重该通道暂停、当天明确拒绝、读信轮次、待办和忙碌。主动点击不计自动每日限额，也不自动重试；服务端独立持久化 write/catch 一分钟冷却，前端显示倒计时。
- human：写信仍是 bottle.request，打捞直接 doCatch('human')，不推送 bottle.request/reading，直到点击回信。held 持久化 caughtBy，重启不丢来源。读信保留 external 事件与标题/正文，不混入系统指令、任务号或信件号。
- 独立网页新增 /wake（既有本机 POST 防跨站校验不变），与扩展页签 invoke('wake') 共用暂停/恢复/间隔实现，输入在服务端校验。新增控件确实出现在独立信箱网页，不只是在扩展页签。
- /draft 与 status 请求会等待合并的短间隔额度刷新。ctx.refresh() 只在扩展面板挂载期间可用；内置配置页不会挂载扩展客户端，不提供自定义页头定时器插槽。原有配置页 badges 明示快照，不跨根 DOM 注入、不改宿主。webUi() 保持同步廉价声明，不在 manifest 生成中发网络请求。

仍为本地 0.4.2，未发布。
