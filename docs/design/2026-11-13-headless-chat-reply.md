# 共读结束后的聊天回信（0.9.2）

0.9.1 修复了工具注册，但 bottle_reply 的 letterId 虽为可选字段，后续聊天回信分支却要求必须传它。自动共读结束会清理逐轮授权；伙伴另行请求回复时，模型只传 text，便落回桌面授权检查，收到要求点击网页的错误。

无头开启、没有现存桌面或 Controller 授权时，默认目标改为唯一的 held。显式传 held 或真实当前信编号仍可；错编号拒绝，不将聊天消息编号当信件编号。无持信时直接说明没有回信目标；World 停止时拒绝。原文还未成功投递或读取时，先要求 bottle_read_letter，丢弃的共读事件不授予权限。已有只读/纸条授权、待投递共读和自动共读当轮限制优先，不能借省略编号绕过。

新回信仍为 manual，沿用原信期限，不调用服务端定时保护。寄出仍使用真实 draftId 和当前 revision，并按工具/提示词规则等待伙伴明确确认。不开启无头时不增加权限，不改变已有桌面定时稿、Controller 入口或页面。

真实 Core 回归分为自动共读时起草、共读结束后另行聊天请求两条路径；后者不传 letterId，随后独立确认轮列稿、看稿并寄出。测试全部使用合成模型、临时目录和内存服务端，不读取真实聊天。另测关闭拒绝、只读拒回、错误目标和没有持信。

仅客户端更新至 0.9.2，服务端继续使用 0.9.0。
