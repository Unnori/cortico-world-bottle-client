# 可选的其他设备信箱入口

按本次用户指定方案实现：回环监听保留零鉴权；另开默认关闭的 IPv4 监听，共用 page.ts 的 handlePage 与 HTTP 适配器。card.ts、host-open.ts 不改动。

配对令牌由 ctx.storeSecret/secret 保存在部署中，开启时生成。二维码在框架面板内本地生成，链接 fragment 承载令牌；配对页立即清除 fragment，再 POST 交换 HttpOnly、SameSite=Lax cookie。Cookie 与令牌绑定，重置立即撤销旧配对；正常重启保留配对。裸 HTTP 可用，界面红字说明明文传输风险，不额外阻止。

配置：lanEnabled=false、lanPort=7798、lanPublicUrl=''，均需重启。启动失败只影响对外监听，回环仍可用。地址来自当前网卡与可选公开 origin，通过 mailbox/status.links 提供给页内入口（按后续要求不在顶栏声明 webUi().links）；链接本身不含凭据。手机浏览框架面板时选择服务器可达链接，不错误打开手机自己的回环。

信箱页签增加独立扫码卡片：状态、可达地址、显示二维码、重置配对、明文提示与配置引导。配对资料只通过已认证的框架面板 RPC 提供，不在匿名监听、公共链接、日志或模型环境中提供。共享信箱路由、正文授权与人工确认不变。

验证涵盖默认关闭、两监听独立、未配对拒绝、跨站与无效令牌拒绝、Cookie 复用与重置、重启持久化、错误配置与端口占用、面板链接选择和二维码呈现。
