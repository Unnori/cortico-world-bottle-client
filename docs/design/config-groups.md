# 原生配置页分类整理

## 目的与边界

将堆在同一个「漂流瓶」分组中的选项按用途排列，优先显示常用设置，保持所有现有字段、默认值、热更新语义与已保存值。只改扩展，不增加试听或其他功能，不修改宿主 DOM、CSS、内核或网页信箱。

## 实现选择

仅重排原单组不能提供分类标题；自制配置面板会重复表单、保存与路径选择逻辑。采用框架现有 ConfigGroup 数组，由原生配置视图按声明顺序渲染组标题和字段，不引入自定义 UI。

按显示与通知、海边邀请与提醒、桌面音效、来信提示音、回信提示音、其他设备访问、连接与调试排列。邀请开关与各自间隔成对摆放；声音来源、包内音效、本机路径保持相邻；网络与调试选项放后面。

`BOTTLE_CONFIG_FIELDS` 保留唯一字段声明，`BOTTLE_CONFIG_GROUPS` 按明确的字段列表分类，每个字段只登记一次。同一个 `worlds.bottle.*` 路径继续写回原位置；仅配置组 ID 拆分。`world:bottle` ID 保留给「其他设备访问」，以兼容信箱页签已有的 `ctx.setConfig('world:bottle', ...)`。其余组 ID 带固定后缀。框架 readGroupValues / coerceGroupValues 与热更新继续负责存取，无配置迁移。

## 验证

校验组和字段顺序、覆盖与唯一性、默认值合法、原路径读写、跨组隔离、LAN 保存 ID；再运行原有功能回归。使用真实宿主配置渲染器和纯模拟值做浏览器检查，不读取或写入运行中的私有配置，不自动重启宿主。运行实例未重新加载 World 时明确报告尚未生效，不以模拟页面代替真实实例验收。


## 2026-11-02 验证结果

- 分组相关 147 项测试全部通过；World 与 WebUI 类型检查、面板构建通过。
- 浏览器直接加载框架原生 createConfigView、表单控件与样式，以纯模拟配置验证 1040px / 390px、浅色 / 深色共四组布局：25 项设置按七类完整显示、无横向溢出，原生音频文件选择按钮仍在；修改仅向所属组自动保存，LAN 仍使用 world:bottle。
- 容器查询依赖宿主的 webui-content 容器，隔离测试必须保留该容器；不能只缩 iframe 而省略容器后将布局差异归咎于产品。
- 运行宿主 17788 的 JS/CSS 与本地摘要一致，但 manifest 仍仅登记旧 world:bottle 配置组。未自动重启，尚不能声称实际窗口已显示七组；需完整重启 Coopanion 后重新打开配置页。只读核对页已关闭。
- 完整套件 473 项中 470 项通过、3 项音效测试失败。检查发现工作区音效包现有 22 个新 WAV，但默认 incoming/default.wav、reply/default.wav 已不在目录；保留这批音效文件和默认选择，不在配置分类任务中擅自替换或补造文件。该问题与分类无关，待音效维护任务处理。


后续音效修正：人已指定来信 New_notifications_1、回信 New_notifications_3 作为默认，客户端与测试同步更新后完整 485 项测试通过；上述三项音效失败不再存在。目录隔离与根目录共享规则见 reading-and-sound.md 及 world/sounds/README.md。
