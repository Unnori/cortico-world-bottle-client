# 1.0.0 待发布：本地信箱和寄送回执

2026-11-16。修复此前已定位并经用户确认的两处客户端缺陷；仅保存在本地，不提交、发布、部署或重启真实桌宠，不修改 E:/BottleWeb 或服务端。

## 行为

- 读取本机 `/draft`、`/notes` 和面板 status 时，立即返回本机已经保存的草稿、信册、纸条和最近状态。后台查询仍会更新，下一次页面轮询可看到结果。
- 复用原有额度刷新节流及请求合并，避免一个挂起请求引出更多并行请求。普通动作的资格校验和真实发送请求仍按原逻辑等待结果，不把缓存额度当作发送成功。
- Windows 卡片被操作后暂停自动收起，并取消正在进行的关闭动画；业务失败、传输失败或结果未知时继续显示反馈。发送失败不删除草稿、不添加寄出记录、不自动重投。
- 明确成功且 close=true 的动作保留原来的关闭流程；无人操作的卡片仍按已有时长自动收起，手动关闭仍可用。成功寄出的新信从待办移入已发出，待办为空不表示正文丢失。

## 实现取舍

仅缩短网络超时仍会让本地阅读依赖远端；逐个修改网页 loading 文案也不能消除阻塞。因此在读取边界直接返回本地快照，将现有同步查询改为后台刷新。状态灯未新增网络诊断协议，仍表示最近一次探测结果。

卡片复用原渲染器，只停止原有计时和关闭动画，并改进未获得寄送回执时的提示。卡片本地 HTTP 按钮仍使用既有同步 WebClient；本次不宣称已解决等待请求期间的 WPF 线程阻塞，也不重写通知布局或发送协议。
