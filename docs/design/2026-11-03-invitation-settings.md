# 邀请次数、最近读信与占用恢复

状态：已实现，未发布。沿用 0.6.0 包版本，发布时再定版本号。

## 配置与展示

三种邀请分别新增 DayLimit 配置，默认 3、范围 1—24 整数，与对应 IntervalHours 紧邻。原生配置、World 信箱页签、独立网页共用 ctx.persist；调度器保存上限并在每次投递前重验。修改上限不清零今日次数、不提前触发邀请，自动补试计入上限，手动邀请仍独立且保持一分钟冷却。

保留现有页面结构，将最近一次邀请结果移出折叠设置，放在两个行动按钮下方的单独文本框，沿用主题颜色与过渡。无回应显示桌宠名；明确 no_idea、投递失败、取消各自区分，不将主动拒绝说成失败。

## 提示词

打捞邀请附最近一次打捞的署名（无署名则使用匿名名）和标题，旧信无题则明确未题名。重复捞到同一封时使用 lastCaughtAt，不修改信册首次收录时间。写信邀请附最后一次成功授权读信的时间和署名，并增加“结合你的近况”。记录 lastReadAt，旧数据没有该时间时省略，不能拿收到信的日期冒充阅读日期。邀请不包含正文或信件 ID。写信和打捞邀请现在可能引用陌生人的署名/标题，标记为 external 事件；纯本地待办计数提醒仍为 internal。

## 待处理信不一致

代码中发现三条路径：

- dismissHeld 把所有网络错误当成已经放回，清掉本机 held 与回信稿，而服务端仍 caught。
- keepHeld 对普通信只清本地状态，未解除远端占用（页面通常仅给无正文信展示珍藏，但接口也须防护）。
- 同一 World 实例再次 load 时，磁盘 held 为空不会覆盖旧内存。

现在放回/收好需等服务端成功，或明确 gone/not_found 后再清本地；网络失败保留来信、草稿与授权状态。load 先重置本地槽，再加载磁盘。

catch 返回 holding 时，新服务端附现有占用的 ID、匿名名、窗口和打捞时间，客户端恢复至信笺桌；不重新扣额度，正文仍只落本地页面，工具不暴露正文或 ID。旧服务端在仍有本地记录时可逐个验证近期候选来恢复；记录完全丢失则需要更新服务端。不会为了修复占用而自动把未知信件丢回海里。

服务端无需配置/环境变量/数据库迁移，但需按现有海面清空流程安排代码更新和重启；本次未部署。
