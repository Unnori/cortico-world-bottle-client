# 音效选择、反馈入口与新信定位

状态：本地实现，未发布；沿用已有配色与页面结构。

## 音效

旧试听未停止、旧请求加载较慢，以及移动端 select 的 change 提交时机，可能让页面选项与听到的声音错位。选择变化时使旧请求失效并停止对应声音；每次试听捕获当下选择，新的试听取消之前的试听。通知读取同一份当前选择并校验选择版本，音频请求使用 no-store 避免复用旧文件内容。来信/回信音效分类、本设备保存与 Windows 独立配置规则不变。

测试除标签/URL外，也检查传给播放器的音频数据；浏览器验证实际包内奶龙与通知 1 的 WAV 解码数据，声音不输出到用户扬声器。

## 反馈

按最新调整，删除行动区之后新增的反馈整栏，网页入口移到顶栏外观按钮旁，只显示线条图标与“反馈”，使用透明背景和细描边，不添加说明文案。继续打开原来的便笺弹窗，保留 GitHub 与群内反馈。弹窗和 World 信箱页签启用腾讯文档收集表入口，统一链接在 world/feedback.ts；二维码由同一链接本地生成，折叠放在便笺内。便笺以明显边框显示当前 World 版本，面板显示“反馈收集 · V版本号”。版本从扩展自身 manifest 读取，经 status 交给无运行时依赖的浏览器面板，不使用宿主版本。

## 新信定位

为页面草稿传入创建时间，来信传入打捞时间。当前待处理卡片 key 与上一轮比较，新增/改写后将最新卡片 scrollIntoView 到中央。无新增的额度轮询不滚动；移除后再次出现可重新定位。同一正文重写通过时间识别。普通页面使用平滑滚动，系统减少动态效果时立即定位；不抢键盘焦点，反馈弹窗打开期间延后。

浏览器测试覆盖手机短视口中新来信、新草稿、重写、普通轮询不移动以及弹窗关闭后再定位。后台浏览器动画帧会暂停，测试中心位置时模拟系统减少动态效果；平滑滚动参数另有单测覆盖。
