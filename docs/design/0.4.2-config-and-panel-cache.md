# 0.4.2 配置同步与扩展面板缓存

> 本设计已并入 0.5.0（2026-11-02）；下文的 0.4.2 与“不发布”为设计时的版本编号和阶段安排。

## 配置

在原配置页声明写信邀请、打捞邀请、待办提醒的独立开关与 2—24 小时间隔。使用框架已有 ConfigGroup 与热配置活引用，不修改宿主。独立网页、扩展面板和工具表达的人为暂停都通过 ctx.persist 写回 worlds.bottle；后台检查和可见快照按值同步到调度器，值没变不重排时间，也不清除当天拒绝和失败。恢复按钮仍能解除当天拒绝/失败。

defaults() 为六个配置项提供合法默认值。升级时以只读方式读取旧 bottle-wake.json 的暂停和间隔，同时检查部署 config.json 是否显式保存过对应键，区分新注入的默认值与人选择的值；显式部署配置优先，避免默认开启覆盖旧暂停。构造不写磁盘、不创建任务。原始调度文件继续保存任务、暂停、历史与日期状态。

## 框架根因

- Cortico/src/web/server.ts：扩展资源路由按 packageName / version / basename 定位，sendFile 使用 maxAge=1y、immutable。内容变化但 0.4.2 和 webui.js 文件名均未变化，缓存地址不变。
- Coopanion/console/advanced/console-pages/loader.ts：成功模块按 pageId 缓存在 loaded Map，load 先返回缓存，不比较新的 asset 地址；仅切换页签也不会换实现。
- Coopanion/console/advanced/console-pages/host.ts：refresh 重新读取清单并刷新页头，不重新挂载面板。
- Cortico/src/extensions.ts：扩展入口使用普通 import(fileURL)，只重启 World 实例并不会清除进程已导入的模块；服务端资源表同样在进程内保留。

## 扩展内解决方案

构建 JS/CSS 后用 SHA-256 的前 12 位作为文件名摘要，原子更新 package.json 的 cortico.webUiClient / webUiStyle 路径。固定名兼容入口保留，但新清单不再指向它们。无需修改 Cortico 或 Coopanion。首次启用必须完整重启软件以重载资源表和设置窗口的模块缓存；之后每次修改扩展也遵循此加载边界。

验证清单指向字节确实匹配摘要，加载实际打包产物并检查三组控件；另以本地框架的真实 loader 与 DOM 工具做工作区集成核对。此类工作区测试不引入扩展对宿主源码的运行时依赖。
