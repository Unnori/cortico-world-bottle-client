# deploy11 客户端适配

## 范围

调整客户端回信窗口的消费逻辑，保留工作区已有的服务端代码和死锁恢复实现。按后续要求将此次修复记为 0.7.2；只做本地修改和验证，不提交、不推送、不发布，不部署或重启真实实例。

## 约定

- `Quota.reply_window_hours` 为可选字段；保留 `REPLY_WINDOW_HOURS = 72` 供老服务端兜底。
- World 的 `setQuota` 统一吸收 `/quota` 与动作回执中的正有限数。缺省或无效字段不覆盖已知有效值；本轮从未收到有效值时用 72。启动时重置记忆，避免重启接入老服务端后遗留旧值。
- `recoverLegacyHeld` 按原打捞时间与当前窗口推算，过滤已超时的历史记录。正常打捞缺少合法 `windowUntil` 时也使用当前窗口兜底。
- 已有合法 `windowUntil` 是这封信的截止时间；页面和桌面卡片继续共用 `hoursLeft` 按它倒计时。服务端热载只影响新打捞，不追溯缩短已发放窗口。
- 无原信元信息且无可恢复历史才调用无 ID 的 `/dismiss`。释放失败不声称成功；落盘失败且释放失败时保留内存中的原信。种子信不走通用释放接口。

## 验证

新增 `tests/world-reply-window.test.ts`，覆盖 24 小时窗口、动作回执与额度刷新、缺失截止时间、有效截止时间优先、旧服务端/无效字段、原信恢复/过期、热载不追溯和同实例重启。并运行 `tests/holding-deadlock.test.ts`、类型检查及全量测试。所有信件、时钟、额度和状态均由隔离测试实例生成。
