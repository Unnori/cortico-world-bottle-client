# 1.0.0 本地 SQLite 与数据迁移、备份

状态：2026-11-16 用户已确认按设计实施。只修改本地扩展，不提交、部署或迁移正在运行的真实实例。用户已选择保留迁移前备份。

## 目的与使用方式

把散落的本机信件、纸条、草稿、星标、提醒状态、字体绑定、主题及自定义素材收进 SQLite。旧版信件正文、装饰、共读计数、真实收信时间及失效未寄稿继续可读。扩展页新增「数据迁移与备份」卡片，集中提供迁移状态、分类备份和导入预览。信箱原来的导入、导出按钮移到这里，信箱保留前往此处的提示及本设备素材收集入口。

## 方案选择

- SQLite：沿用 TypeScript 与 Node 内置 SQLite，无额外本地编译依赖，支持事务、逐条记录与素材 BLOB；采用此方案。
- 外部数据库：需要玩家安装或维护服务，不适合桌宠扩展。
- 继续合并 JSON：无法满足全面迁移 SQL，放弃。

Node 需要支持无需实验参数的 node:sqlite（最低 22.13）；不支持时给明确升级说明，不能默默创建新空信册。本轮使用单连接短事务和 DELETE journal，不依赖旧 SQLite 的 WAL 多连接行为。重型备份压缩/解析采用异步操作；运行时按记录写入，不再整册重写磁盘。框架 secret 和扩展配置仍由框架接口管理，不能自行搬动宿主配置。

## 存储及旧版迁移

数据库位于本扩展数据目录 bottle-local.sqlite。信件、回信、草稿、纸条与星标为有主键的独立记录；设置为限定键值；自定义字体、背景、音效和素材保存为带摘要、类型与大小的 BLOB。内置信纸/SVG/音效仍是只读安装资源，不复制进数据库；云端字体缓存可重新下载，不默认备份。

首次使用新版数据层时，读取固定白名单旧文件和素材目录，先保存原字节的迁移前备份，再以事务迁入；校验数量与内容摘要，提交并标记成功后，才停止使用旧文件。迁移是幂等的，失败不删旧文件、不承认迁移成功。原文件清理由已验证迁移结果控制；备份可在卡片下载。损坏文件明确列出，不静默变成空数据。新安装直接创建空库，无假迁移。

迁移必须保留本机身份、现有持信、定时稿及纸条寄送回执，迁移本身不触发发信、通知或模型授权。数据库中有正文的数据随对应往来删除/清空；用户主动保存的备份由用户保管和删除。Windows 卡片 JSON 及 Bridge 发现文件属于临时进程通信，继续按生命周期生成和删除，不作为持久权威或备份来源。

## 分类备份

复选项：信件与回信、未寄草稿、小纸条、系统来信、星标、涂鸦与装饰、自定义字体与笔迹绑定、自定义音效、主题与背景、阅读偏好。默认全选，可只选一部分。信件自身装饰和正文保持完整；「涂鸦」额外选项指自定义素材库，不把未选中的正文带出。备份只包含用户新增/修改的音效，内置原字节排除；旧安装目录手动添加的音效、当前桌面所选本机音效允许只读收集，未知路径不从导入文件执行或读取。

备份使用有版本、类别、校验摘要和大小上限的压缩文件；兼容导入旧 v1/v2 JSON 信册。导出不包含 secret、配对、Bridge 凭证、删除凭据、记忆授权或可自动寄送凭据。恢复草稿只作未确认/失效留稿，恢复纸条标 imported 且未知发送作 unconfirmed，不会补寄或播报；普通历史导入不能恢复远端占用资格。

浏览器本设备的声音和阅读偏好不能由宿主跨源读取。信箱提供明确的「收集本设备素材」操作，将当前设备自选音效与偏好送入本机 SQLite；说明会传至本扩展所在电脑，配对入口仍受现有鉴权保护。只有点击才收集，不悄悄上传。缓存云字体不收集。恢复的设备偏好/音效由当前设备主动选择应用，避免覆盖其他设备的独立选择。

## 导入比较与替换

先上传到有限大小的临时区，整份校验后生成短时预览凭据。对比区只列本机和待导入的信件数量（寄出、收到、回信、系统信及合计），不展示正文；另外明确本次涉及的类别名称。操作为「保留本机」「合并（本机已有优先）」「替换所选类别」。未包含类别不受替换影响。

替换默认勾选「先备份被替换的数据」，可由人取消。只有新备份成功落盘后才允许替换，提供下载；取消不改数据。预览记录数据库版本，确认时若本机又收到信/有任何相关数据变化，要求重新比较。重复确认同一凭据不重复执行；过期、错误凭据拒绝。所有选定类别在一个事务提交，失败回滚，随后重载各本机视图并使旧权限/事件失效。若有发送/同步进行中先等待，防止旧内存写回覆盖恢复结果；全程不接触中央服务端。

现有 held、定时稿、待确认寄送纸条始终受保护，导入不能覆盖或删除这些活动记录及其原往来。当前草稿槽非空时，不能通过替换草稿撤销原稿，应提示先人工处理或取消选择草稿类别；历史替换仍保留活动往来。导入草稿只恢复到空槽；已失去持信条件的回信只作为失效未寄表达保存。

迁移前与覆盖前备份在卡片中列出，提供逐份下载、删除，不自动过期。删除信件或清空信册只作用于当前库，若存在本机备份必须明确提示备份仍保留，可到此卡片删除；不得宣称已清除所有正文副本。下载后的副本由用户自己保管。

## 入口与传输

沿用现有 WebUI 原生组件与信箱纸张配色，新增一张底部卡片，不重做信箱。卡片分「当前保存方式」「选一份备份」「导入前对比」三段；忙碌和错误均在原位置显示，可取消预览。窄屏对比逐项换行，键盘可达、明暗主题与减少动态效果保持。

大文件使用有大小、顺序和时限约束的分块传输，避免突破宿主 RPC 单次请求上限；写临时文件，不在配置状态或日志塞正文。导出同样分块下载。只暴露给人的面板和配对信箱入口，Bridge/模型工具不新增备份、覆盖或读库能力。

## 验收

真实 SQLite 旧格式迁入、重复运行、重启与内容一致性；事务中断/磁盘写失败不删原件；每个类别独立备份、混合选择、排除内置音效和敏感凭据；旧 JSON 导入；坏文件/摘要/压缩炸弹/路径拒绝；预览不改数据、过期/陈旧/重复确认、替换前备份失败、事务回滚；导入不自动发信/补寄/授权；真实浏览器完整导出—预览—取消/合并/替换及窄屏明暗；原有测试、类型、自描述、打包清单检查。实际运行实例只做只读资源检查，不自动重启。

## 本轮不做

不改中央服务端、既有寄送策略、公开 API，不加云同步，不上传到第三方，不把普通备份声称为加密备份。旧版本不能直接读取新 SQLite；若要退回旧版，需先下载并通过兼容信册备份恢复历史，不能直接运行旧版覆盖本机新记录。
