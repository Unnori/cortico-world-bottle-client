## 先认识三个地方

**桌宠**负责表达、起草和与你交流。它可以决定暂时不写、不捞，不必用完额度；信不要求积极、深刻或某种统一文风。

**本机信箱**是你自己的信册和操作页，由扩展在电脑上提供。草稿、已收到的正文、寄出记录和外观保存在本机部署数据中。电脑不运行 World 时，手机也不能靠这个入口继续操作。

**海边服务器**负责匿名漂流、额度和投递。电脑里的本机信箱端口不是海边服务器端口。教程、落地页和碎碎念网站也不是你的私人信箱，上传静态网页不会启动 World、同步私人信册或建立 Bridge。

| 入口 | 用来做什么 | 容易混淆的地方 |
| --- | --- | --- |
| 宿主设置 → 漂流瓶「信箱」页签 | 打开信箱、查看状态、邀请设置、设备配对、导入导出 | 这是扩展面板，不是全部信件正文列表 |
| 独立本机信箱网页 | 看信、审稿、寄送、回海、共读、外观和网页声音等 | 默认从 `http://127.0.0.1:7796/` 开始，实际可能顺延 |
| Windows 桌面卡片 | 新信、草稿、回信等便捷提示与操作 | 收起卡片不等于放弃草稿或归还信件 |
| 手机配对网页 | 在其他设备操作同一台电脑的信箱 | 用独立 LAN 监听与配对 Cookie，不是第二个海边账号 |
| 本机 Bridge | 让可信程序按权限调用部分功能 | 默认关闭，普通 Bridge 和 Controller 分别授权 |

## 安装启用与第一次使用

1. 在宿主的扩展管理中安装 `cortico-world-bottle`。使用本地开发目录或 tgz 时，按宿主的手动安装入口选取。源码 manifest 要求 Node.js ≥22、World API 6；宿主自身的 Node 要求仍需同时满足。
2. 完整重启宿主以装载代码和面板资源。激活漂流瓶 World；它默认 `enabled:false`，装了但未激活时没有运行能力。
3. 保持默认海边 `https://bottle.sqnori.com`，除非你确实在自建服务器。切到漂流瓶「信箱」页签，等待额度状态出现，点击「打开信箱」；也可在聊天里请桌宠打开信箱。
4. 第一次可以请桌宠写一封，等它起草后在信箱审阅并寄出；或打捞一封，选择共读、回信或归还。
5. 无头、LAN、Bridge、Controller 和星笺记忆总开关均是可选能力，默认关闭。基础写信、打捞和网页确认不需要打开它们。

更换海边地址、端口或网络监听设置需要重启漂流瓶 World；**升级代码**应完整重启宿主。请勿为了排错清空身份文件或全部数据。

源码依据：[manifest](../package.json)、[默认配置](../world/config.ts)、[World 启停和面板](../world/world.ts)。

## 写信与草稿

### 怎样写与寄

你可在信箱邀请桌宠写信，也可在聊天里提出想法。桌宠用 `bottle_write` 保存新信稿，自己决定表达什么；默认你在网页或卡片上看过以后，选择寄出、请它重写或放弃。

- 正文去掉首尾空白后，**1—120 个 Unicode 码点**；标点、空格、换行会计入。它不是字节数或模型 token 数，组合 emoji 也可能占多个码点。
- 新信标题可不填；填了须为 **1—20 码点、单行**。标题和正文分别计数。回信和小纸条不加标题。
- 图案和信纸参数不占正文的 120 字，但有自己的大小限制。
- 发给陌生人的正文、标题、图案和 SVG 都不得夹带伙伴真实身份、联系方式或本机私密信息。工具提示词也明确要求这一点；这不等于一个能识别一切隐私的自动审查器。
- 普通网页没有供人随意改写桌宠正文的编辑器；想换说法请它重写。Bridge 普通接口可由外部程序投入自己的待审新信，这类稿会标出来源。

### 草稿的两个位置与版本

可同时保存一份新信稿和一份回信稿。它们有不同的 `draftId`，以及从 1 起的 `revision`。修改正文、标题或装饰会使旧确认失效；重建稿件使用新 ID。

网页、卡片、无头工具和 Controller 都按实际草稿 ID 与当前版本处理。看到“版本已变化”时，重新查看新稿后再确认。`letter/reply` 是类型，不是可用于确认的草稿 ID；聊天消息编号也不是信件 ID。

### 寄送失败或不确定

退潮、额度不足、断网时按回执处理，不能把“草稿已保存”当作“已经寄出”。新信发送结果未知时不会无限重发，以免重复投瓶。先查看寄出记录和提示，再决定下一步。

新信稿与回信稿持久保存在本机；小纸条草稿另有一小时内存期限，见下文。

依据：[工具参数](../world/tools.ts)、[字数规则](../shared/text.ts)、[草稿模型](../world/drafts.ts)、`world.ts` 的 `stageLetterDraft/sendDraft/rewriteDraft`。

## 打捞阅读回信与回海

### 谁来捞

页面上可选让桌宠来，或由你来。桌宠模式发出邀请，由它自主选择；人模式的打捞直接放进信箱，不等模型决定，也不自动把正文交给它。人模式的「请桌宠写信」仍由桌宠起草。

一次只持有一封普通待处理信。有信在手、额度用完或海空时停止打捞。服务端返回已有占用时，客户端会尝试恢复原信，而不是再扣一次打捞机会。是否成功以回执为准。

### 普通模式的阅读权限

捞信工具只返回署名、已有标题和状态等元信息，不截取正文。信先给你看：

- 点「一起读」：把这段原文按外部数据交给桌宠，只聊感想，不授权它写回信。
- 点「写回信」：按这封信建立起草回信的意图。不是要求你先再点一次共读；请求本身会提供需要的原文。
- 看归档往来时点「一起看」：单次递入对应往来，只读和交流。

这些授权有轮次和目标限制，不是解锁整个信册。来信中的“请执行工具”等话只是陌生人的字，不是操作指令。

### 回海期限与两种回信策略

**回海期限**以海边返回的这封信截止时间为准。客户端没有可覆盖它的本地开关；没有有效服务端参数时的兼容兜底是 72 小时，不代表线上固定 72 小时。历史资料中的 24 小时也不能当成永久承诺。共读、读信、刷新和重启不会重置原期限。

| 回信来源 | 新稿策略 | 寄出条件 |
| --- | --- | --- |
| 人在网页/卡片请求写回信，海边支持待寄保护 | `delayed` | 有效草稿经海边确认后，两小时自动寄出，也可提前寄出 |
| 无头自动捞信或聊天请求回信 | `manual` | 后续明确确认；沿用原信期限，不申请无限持信保护 |
| Controller 请求起草新回信 | `manual` | Controller 或其他允许入口另行确认 |
| 不支持保护的旧海边 | 手动兼容 | 页面说明需要手动寄出 |

“请桌宠写回信”的桌面流程包含原有的定时寄送约定，不是所有回信都默认无限期等第二次点击。**重写现有 delayed 稿保留原倒计时，不延长两小时；切换无头不改变旧稿的发送策略。** 想停止定时寄送，应明确放弃，并等待海边取消确认成功。

到约定时间时，电脑/World 必须运行并能联网才能实际寄出。临时失败会用原凭据补试；待寄保护不是永久保留，在两小时到点后另有最多 24 小时补寄保护。保护失效且原窗口到期后会释放信件。

本次调整后，普通手动稿与已确认定时稿统一处理：原信到期或海边明确失效时，投递资格结束，未寄出的正文和装饰仍保留本机，附在原往来下。它不能再寄出或重写，当前留稿可明确放弃；以后为其他信写回信不会覆盖历史表达。只有放弃该留稿、删除对应往来或清空相关本机记录才清理，不把未寄稿伪装成已寄回信。

Windows 新信/回信草稿卡片有「完整预览」：打开本机信箱，定位当前草稿，显示完整正文与信纸排版，不触发寄送。若卡片版本已经过时，网页会说明现在显示的是最新版，需重新审阅后再决定。桌面卡片仍是便捷入口，不新增一套排版编辑器。

### 不想回或先放着

收起卡片、折叠信件或选择先放着，只关闭显示，期限照走。归还会释放当前持信；归还太多次是否沉底由海边规则决定，不能按旧教程写死“五次”。普通信的「收好」也复用既有释放/收藏规则，不能借此永久占用可回信的瓶子。邮局信、失效信的珍藏则是本地保存。

归还或取消定时稿失败时，保留本地信件/草稿以避免状态错位。不要通过手删 JSON 来强制清占用。

依据：`world.ts` 的 `doCatch/doReply/authorize/dismissHeld/keepHeld/checkAutoReply`、[期限修复说明](../docs/design/2026-11-13-reply-draft-expiry.md)、[海边请求清理逻辑](../server/app.ts)。

## 邮局系统信与收到的回信

**海边邮局信**是群岛故事等系统投递，有明确邮局来源和作者署名，不伪装成真实来客。独立通道领取，不消耗普通打捞额度，不占普通持信位置，不能回信，可以保存。手中已有普通信时客户端暂不领取系统信；有没有系统信、何时发以及每天数量，由服务端投放规则决定，不保证每次打开都有。

**收到的回信**是别人回复你寄出的原信，在「收到的回信」与对应寄出记录中查看。回信到达不表示允许与对方无限来回聊天；后续短回应使用小纸条功能。

普通模式：系统信只给到信提示，回信只通知数量和相对时间；正文默认留在信箱，点击一起看才交给桌宠。

本次无头调整：新系统信和回信全文以**外部延迟事件**交给桌宠自主阅读，默认主动谈自己的感想，伙伴问“它写了什么”时才转述原文。系统信仍不单独唤起，回信按宿主安静间隔合并。自动到信轮次只读，不顺便起草、发送或放弃任何稿件。

后台通常每分钟查回信/小纸条、每五分钟查额度、每十分钟尝试系统信；启动与某些页面操作也会同步。网络、持信、服务端排程和宿主事件队列都会影响实际时间，**不是投递时效保证**。

依据：`world.ts` 的 `refreshMailbox/refreshSystemMail/queueHeadlessMail`、[事件目录](../world/events.ts)、[种子投放规则](../server/tuning.ts)。

## 小纸条

小纸条是**原作者收到回信后，再向回信者留一句话**。不是给任意信件发消息的入口，也不是让所有收件人继续回信的第三轮按钮。

1. 你寄出的信收到回信后，在对应回信下邀请桌宠留纸条。
2. 桌宠读这段原信和回信，用 `bottle_note` 写 1—40 码点，不带标题。
3. 你可请它重写、确认寄出或放弃，不能人工填写/修改纸条正文。
4. 寄出消耗一次**打捞机会**，不消耗一次新的普通寄信机会；额度不足暂不能寄。

每段往来只能留一张；草稿仅当前 World 内存保留最多一小时，重写不延长最初期限，重写失败保留原稿。停止 World、到期、寄出、放弃或删除往来会清理未确认草稿。

收到的纸条会自动通过外部事件递给桌宠，原来就不要求逐张点读。**无头关闭时仍保留这一既有行为**；本次调整仅在无头开启时明确要求“主动分享感想，正文等伙伴询问才转述”。自动到纸条不附原信和原回信；点「一起看」才同时递上完整往来。

纸条贴在原往来下；本机没有原信时会有对应占位说明。收到的纸条仅“未读/已读”，确认进入桌宠上下文才标已读，打开浏览器本身不改变这个状态。

寄送确认前先在本机保存原文。断网或回执丢失可原文确认重试，不会因同一次纸条重复扣机会；超过七天的安全确认期后停止补试，原文仍保留。服务端未取走的纸条七天到期，ACK 后删除；**本机已收到或已确认寄出的纸条不会七天后自动消失**，仅删除对应往来或清空信册时删除。

本次 v2 明文信册导出包含收到与寄出的纸条、方向、时间、已读与寄送状态。导入按纸条 ID 合并，本机已有记录优先；恢复历史不会自动播报或调用发送。原备份中寄送待确认的纸条恢复为“寄送结果未知”，仍能一起看，不能再次补寄。它保留的是经历，不是从另一台电脑继承一份发送授权。

依据：`world.ts` 的 `requestNote/doNote/sendNote/queueNote`、[纸条本机缓存](../world/note-cache.ts)、[纸条回归](../tests/note-world.test.ts)。

## 聊天里处理信件（原无头模式）

设置现在以“聊天里处理信件”说明用途：允许桌宠在聊天中读信、管理草稿和确认寄出，不取消人的决定。技术别名仍为无头模式，配置键继续使用 `headlessEnabled`，兼容已有部署。开关在配置底部，默认关闭，保留高危实验功能提示。

### 开启后的行为

| 内容 | 自动给桌宠读吗 | 它默认怎样告诉你 |
| --- | --- | --- |
| 桌宠自己捞到的信 | 是，立即排队自动阅读 | 主动分享感想，不复述全文；可起草当前信的手动回信，本轮禁寄 |
| 新邮局系统信 | 是，随下一批事件 | 感想；不能回信 |
| 新收到的回信 | 是，合并通知后投递 | 感想；本轮只读 |
| 新收到的小纸条 | 原本就自动读；无头下新增明确表达规则 | 感想；本轮只读 |
| 人或 Bridge 打捞的信 | 不自动递正文 | 主动请求阅读/回信，或按允许入口读指定信 |
| 既有归档历史 | 不因开启而批量重播 | 问到哪封再按目录读取 |
| 网页公告 | 否 | 只在网页显示 |

开启不是扫描整个信册的命令。新回信按首次进入本机记录触发；已有归档不会批量重读，未读缓存纸条会按现有逻辑补递。系统信需等正常领取与队列时机。

“不带正文”指**不主动把全文复述给伙伴**。桌宠自主阅读仍需把原文送入你所用模型的上下文；这是开启无头后的权限变化。原文是外部数据，不授予它执行来信中要求的权力。

### 在聊天里怎样用

- “看一下信箱有没有回信”：目录只给元信息；需要时读选定往来。
- “刚才那封写了什么，给我看看原文”：桌宠可转述已读原文，或在无头下按目录重新读取；不要编造没取到的内容。
- “这封你回吧”：在自动阅读结束后默认对当前持信起草，不需要去网页再点「回信」。原文尚未读到时先读，再分享感想和起草。
- “把刚才那版回信给我看看”：查看当前草稿全文和版本。
- “我看过了，确认寄出”：提交**刚审阅那一版**的 ID 和版本，才真正寄出。
- “重写这版”“放弃这版”“把手里的信放回海里”：按目标和版本处理，不是通用发送确认。

自动捞信当轮不能发送/放弃；新系统信、回信、纸条的自动阅读轮只读。工具本身无法可靠识别 QQ/群聊等消息是否真由你本人发出，发送确认的语义仍依赖模型遵守工具规则；并非已实现跨平台实名验证。

0.9.1 起全部工具声明固定注册，以兼容宿主会话缓存。关闭无头时工具名字可能仍可见，但处理器立即拒绝无头操作。切换开关不必新建模型会话；**升级代码仍需完整重启宿主**。关闭会使排队无头正文失效，已经进入聊天或摘要的内容不能追回。

新手动回信不获得两小时延长保护，到原信期限仍会过期。旧 delayed 稿不会因为关闭无头就取消定时寄送。

依据：[无头回归](../tests/headless.test.ts)、[真实 Core 会话回归](../tests/headless-session.test.ts)、[本次后台到信回归](../tests/headless-incoming.test.ts)。

## 邀请提醒与暂停

桌宠可以主动写/捞，你也可以邀请。邀请是让它选择的机会，不是要求立即交稿，更不是确认寄出。

| 类别 | 默认最短间隔 | 随机实际等待 | 默认每日上限 | 可设置范围 |
| --- | --- | --- | --- | --- |
| 写信邀请 | 2 小时 | 最短间隔的 1—2 倍，上限 24 小时 | 3 次 | 间隔 2—24 小时；1—24 次 |
| 打捞邀请 | 2 小时 | 同上 | 3 次 | 同上 |
| 待办提醒 | 0.5 小时 | 默认 30—60 分钟，最长 1 小时 | 12 次 | 最短间隔 0.5—1 小时；3—20 次 |

自动写/捞邀请需余量大于 1 且无待办等条件；有未处理持信、新信稿或回信稿时改为待办提醒，处理完停止。三类共用一个总开关 `randomWake`，各自还有开关、间隔与上限，网页和配置页同步。

自动补试计入每日上限，手动邀请不占上限，但仍尊重暂停及手动邀请冷却。写信和打捞的页面邀请各有一分钟冷却，人直接打捞不走模型邀请。调设置不会清零今天的次数，也不会立即补催。

桌宠可以用 `bottle_wake_choice` 表示暂缓、拒绝或暂停。网页“恢复”可解除相应暂停状态。关总开关不抹掉各类偏好；模型没完成邀请也有有限补试，不是无限重试。

### 为何有的通知不立刻说

- 你主动点的写信/打捞邀请、共读、回信、重写、小纸条邀请，以及无头桌宠捞信：立即投递 `flush`。
- 新回信和小纸条：按宿主安静间隔合并 `debounce`，不按每封立刻打断。
- 寄出、被捡起、归还、邮局信、海啸状态、已授权星笺记忆：`piggyback`，等下一轮对话或邀请顺带说。
- 不使用抢占/强制中断；网页公告不进桌宠上下文。

无头自动阅读不把系统信改成每封立即唤醒。卡片/浏览器声音是另一条通知通道，不等于模型事件已经投递。

依据：[邀请策略](../world/wake-policy.ts)、[调度器](../world/wake.ts)、[事件定义](../world/events.ts)。

## 信册星笺匣与记忆

信箱按来客来信、海边邮局、收到的回信、寄出的信组织，可折叠和按日期筛选。日期分组不是实时聊天时间线；原信、自己的回复、纸条贴在同一段往来附近。轮询不会把已展开原信反复折回。

阅读标记记的是与桌宠的共读/阅读交付，不是你在网页展开过。当前源码在成功共读及无头自动阅读投递后计数；普通回信起草不单独多计，直接 `bottle_read_letter` 更新持信已读标记而不递增共读次数。一起看收到的回信会附原信，但只增加回信计数。旧记录从 0 开始，不追算；这比旧 README 中“回信起草计一次”的表述更新。

“已寄出”“仍在漂”“被捡起”“收到回信”“海啸/沉底”等状态都按已有回执更新，不能从动画、声音或模型说辞推断成功。

**星标收藏与珍藏处理不同。** 星标是“喜欢这段往来”，不会改变海边持信状态。原信和回信的星标合并去重，星笺匣优先定位回信。

点亮星标后会询问是否允许桌宠记住：

- 只收藏或关闭弹窗：收藏，不递正文。
- 确认记忆：开启相关总开关并授权这段往来，以外部延迟事件提供；后续可用星笺工具重读。
- 逐封撤回、取消星标或关闭总开关：撤回后续读取，排队内容在投递前重验。关总开关会清理逐封授权。

这是扩展管理的可撤回正文权限，不是直接写入核心 Memory。模型已看过的内容可能留在会话/摘要中，无法靠取消星标彻底抹去。无头的逐封读信权限与星笺记忆授权是两个入口，撤回星笺授权不等于关闭无头。

依据：[星标与授权](../world/stars.ts)、`world.ts` 的 `setStar/setStarMemorySetting/readStarMemory/syncStarMemory`。

## 外观字体背景与阅读设置

### 主题与字号

右上角信箱外观可选潮蓝、暖纸、书信、Coopanion 或自定义色，支持跟随系统/浅色/深色。主题和明暗保存在宿主数据，信箱与桌面卡片共用；Coopanion 主题从当前部署已保存主题读取，不要求改内核。暂读不到时保留上次颜色，首次无有效值时回退。

悬浮「Aa 字号」默认正文 26px，可调 18—40px。只改变信内正文、落款和信内标题，标题按正文 1.16 倍；按钮、页面标题、折叠列表不跟着放大。入口可拖到左右边缘，聚焦后可用方向键移动，Shift 加速、Home/End 到顶/底。位置与字号**每个浏览器独立**。

完整信笺保留原文和换行，不补虚构称呼、祝语或写信时间；回信没有新标题。信箱支持减少动态效果，跟随系统偏好停用相关动画。

### 背景

个性化信箱中上传 PNG/JPEG/WebP，最大 **8 MiB**，仅用于信箱网页。存在背景后显示透明度滑条：0% 最清晰，100% 完全淡出，默认 82%。文件保存在电脑部署数据，配对设备可读取；不发给海边、收信人或模型。

恢复默认解除选择，不自动删除上传原图。确需清理闲置图片，应先停用 World 并备份，确认没有被引用再处理 `bottle-backgrounds`。

### 别人的笔迹与我的字体

内置字库从固定 HTTPS 字库站分发。安装包保留清单和许可，不携带整套字体。每位来信人获得稳定笔迹，系统信按署名分配；新字体不洗掉旧绑定，仍在清单但被停用的字体可继续用于旧绑定，清单已撤下的失效绑定才补选。

各浏览器分别缓存字体，首次慢网先显示系统字；下载最长等待约三分钟，失败不挡正文。清缓存会重新下载，不会清掉信册；配对设备共享电脑的笔迹映射，但缓存各自保存。

「自定义我的字体」支持 TTF/OTF/WOFF/WOFF2，最大 **32 MiB**。它改变本地桌宠草稿、寄出记录、自己的回信及相应正文引用/信内标题，不进来信随机池，**不随信寄给对方**。配对手机看同一信箱也可加载；默认写信字体当前为霞鹜悠哉。恢复默认解除选择，不删上传字体。

不要把字体扔进 `world/fonts` 期待自动加入池；当前随机池来自远程清单。内置 SVG 与音频的扩展方法也各不相同。

依据：[外观](../world/appearance.ts)、[背景](../world/background.ts)、[我的字体](../world/my-font.ts)、[字体说明](../world/fonts/README.md)、[阅读控件](../world/page-reader.ts)。

## 提示音与自定义音频

### 先选你要改哪边

| 位置 | 设置和文件存在哪 | 什么时候提醒 |
| --- | --- | --- |
| 漂流瓶配置的桌面音效 | 宿主配置；本机文件可按路径读取 | Windows 新来信/回信卡片出现时一次；草稿和重开旧卡片不重复响 |
| 独立网页「信箱声音 · 本设备」 | 该浏览器偏好；自选文件在该浏览器 IndexedDB | 打开页面并启用后，新出现的来信/回信各一次 |

两边分别设置。修改电脑桌面音量不会改变手机网页音量；手机选的文件不会上传给电脑或海边。本机卡片模式下网页会避免同一通知重复播放。

### 桌面提示音

在桌面音效总开关下设置音量 0—100（默认 70）、末尾淡出 0—5000 毫秒（默认 250，0 关闭淡出）。来信与回信各自选择来源：

- `pack`：选择音效包文件。
- `local`：选择本机音频文件，使用绝对路径；建议 WAV/MP3，其他格式取决于 Windows 解码器。
- `off`：这一类静音。

支持 WAV、MP3、M4A、OGG、AAC、FLAC，单文件最大 **10 MiB**。文件不存在、不支持或播放器失败会安静跳过，不是因此丢信。

### 手动给包内增加声音

以下路径指**实际安装的扩展包**；若只改开发源码而运行的是 npm 安装副本，不会生效：

```text
world/sounds/
├─ shared-wave.wav                 ← 来信和回信都可选，标「通用」
├─ incoming/
│  ├─ incoming_default.wav         ← 默认来信音
│  └─ my-incoming.mp3              ← 只在来信下拉里
└─ reply/
   ├─ reply_default.wav            ← 默认回信音
   └─ my-reply.wav                 ← 只在回信下拉里
```

只扫描根目录、`incoming/`、`reply/` 的直接音频文件，不递归扫描更深层或自建分类。两个目录里同名文件仍是不同选项；文件名去掉扩展名是显示名称。不要使用指向包目录外的符号链接。

重新打开配置选择器/面板、网页刷新后重新加载列表，无需改源码登记。包升级可能替换目录，新增文件要另备份；长期自定义建议放包外，用 `local`。

旧的 `default.wav`、已撤下旧内置 ID 有迁移映射，保留有效自选文件、静音、音量与淡出。历史音效 README 的树状例子曾列旧 `New_notifications_*.wav` 为默认，**以本节和 `DEFAULT_SOUND_PACK` 为准**。

### 网页提示音

在每个设备的信箱页展开「信箱声音 · 本设备」，先点启用，再为来信/回信分别选声音、音量、淡出。选择本地文件后存入浏览器 IndexedDB，不上传服务端。

打开页面时先将已有记录作为基线，不给所有历史信补响；之后轮询发现新来信/回信各响一次。浏览器需要用户交互解锁音频；关闭页面、后台冻结或设备休眠不保证提醒。清浏览器数据可能删除本设备的声音文件与偏好，但不会删除电脑信册。

依据：[音频扫描、大小、默认与兼容映射](../world/sound.ts)、[网页声音实现](../world/page-sound.ts)、[音频目录说明](../world/sounds/README.md)。

## 信纸装饰与 SVG 素材

图案不是整张固定背景。桌宠可选择四角、居中水印，或多图排版，自行决定颜色和位置。装饰是可选项，不取代正文，也不改变信箱整体布局。没有拖拽排版编辑器。

内置目前 32 个图案：原有 3 个加 29 个 SVG Doodles 素材。桌宠用 `bottle_query_doodles` 查询稳定 ID、名称与标签，再写进新信或回信的 `stationery`。

简单写法：

```json
{"v":2,"paper":"line","doodle":"paper-plane","color":"#638c9c","placement":"top-right","size":"small"}
```

复杂排版：

```json
{
  "v":2,"paper":"grid","paperColor":"#fff8ed",
  "decorations":[
    {"doodle":"rain-cloud","color":"#638c9c","x":14,"y":15,"width":22,"rotation":-12,"opacity":0.4},
    {"doodle":"paper-plane","placement":"center","size":"large","opacity":0.12,"layer":"behind"}
  ]
}
```

| 参数 | 含义与范围 |
| --- | --- |
| `v` | 新布局用 2；1 保留旧固定角落格式 |
| `paper` | `grid/line/plain` |
| `paperColor`、`color` | 六位 `#RRGGBB`；纸色独立，墨色自动选黑/白保持对比 |
| `doodle` / `customSvg` | 每幅二选一；内置 ID 或静态 SVG 文本 |
| `x/y` | 图框中心占纸宽/高百分比，0—100 |
| `width` | 正方形图框占纸宽 4—100%，SVG 等比缩放，纸外裁切 |
| `placement` | 四角或 `center`，默认右下；显式 x/y 优先 |
| `size` | small/medium/large：14%/24%/48%，默认 medium；显式 width 优先 |
| `rotation`、`flipX/flipY` | -180—180 度及布尔镜像 |
| `opacity` | 0—0.65，默认 0.28 |
| `layer`、`z` | behind/front；同层 z 为 0—7，默认列表顺序，后者同值在上；前景层另限整体透明度 0.35 |

最多 8 幅图，`decorations` 不能与根级单图字段混用。内置图案不指定颜色时用**本机身份派生的稳定画笔色**，不同桌宠不必都一样；桌宠也可逐信逐图改色。自创 SVG 默认保留原色，指定色才换色。旧 v1 信不被重新染色。

自创 SVG 必须静态、自包含，经过白名单净化；不接受脚本、外链、图片、任意网页内容及不支持的 SVG 特性。单幅净化后 ≤8 KiB，所有自创图合计 ≤16 KiB，整份排版线格式 ≤32 KiB。普通请求另有传输限制，不能靠装饰夹私密信息。

### 手动扩展 SVG 库

1. 将合规 SVG 放入 `world/stationery/`，文件名用小写英文、数字、短横线。
2. 在 `catalog.json` 的 `doodles` 数组登记唯一 `id,name,tags,file`；名称最多 24 字符，最多 6 个标签、每个最多 16 字符。
3. 保留素材许可、作者、来源和修改记录，确保通过校验。
4. 完整重启桌宠进程，再让它查询素材库。目录按进程缓存，刷新网页不能热加载新图。

**仅放一个 SVG 文件不会自动被桌宠发现。** 内置信只传图案 ID，对方也需要同一 ID 的素材；想让新图随信完整传递，用合规 `customSvg`。既有 ID 不要换成别的图，升级安装前备份自己的新增素材。

完整排版需服务端声明 `stationery:1, stationery_layout:2`，且收信客户端支持 v2。只有旧基础能力时降为首幅角落图；无装饰能力则只寄文字并提示，本机保留完整图案。代码 MIT，SVG Doodles 素材另为 CC BY 3.0，不能全按 MIT 转发。

依据：[素材目录](../world/stationery/README.md)、[许可来源](../world/stationery/ATTRIBUTION.md)、[排版契约](../shared/contract.ts)、[SVG 校验](../shared/stationery.ts)。

## 手机平板与其他设备

1. 漂流瓶「信箱」页签中开启「允许其他设备访问」，保存，重启 World。
2. 默认另监听 `0.0.0.0:7798`。确认电脑与手机互通、防火墙允许端口。
3. 显示配对二维码，选择手机可达的地址扫码；不要扫描手机无法到达的虚拟网卡地址。
4. 配对后浏览器保存一年有效的签名 Cookie；正常重启不必重配，清浏览器数据或重置配对后需重新扫码。

本机 `127.0.0.1` 入口仍独立，不因 LAN 开启而变为公开监听。LAN 端口被占用会报错，不顺延；不能用 7797。二维码和配对链接含凭据，不要公开。

`lanPublicUrl` 可填 HTTP/HTTPS 的根地址，不接受子路径、账号或查询参数。它只提供可达地址并参与校验，**不会自动做端口映射、防火墙放行、DNS 或 HTTPS 证书**。公网使用应配置可信 HTTPS 反代；HTTP 会明文传输信件和配对凭据。

手机操作与电脑使用同一信册、草稿和额度，没有独立邮箱。主题、背景、我的字体共享；字号、阅读控件位置、网页音效和字体缓存按浏览器独立。远端发起操作不会唤起电脑卡片，但不会因手机页面开着就全局关闭独立后台通知。

依据：[LAN 监听和配对](../world/lan.ts)、[LAN 设计与验证](../docs/design/lan-mailbox.md)。

## Bridge 与其他程序接入

普通 Bridge 可查询元信息、投入待审新信稿、打捞；Controller 另可预览指定草稿、确认发送、请求回信/共读/重写、放弃和归还/收好。都默认关闭，使用独立凭证，只在本机回环监听开放，不借手机配对授权。

它不是开放全部 Web UI 按钮，也不是批量读所有正文的接口。HTTP 回信请求只邀请桌宠生成手动稿，不能顺手认为发送已确认。完整配置、发现文件、凭证、每个接口字段、PowerShell/Python 示例和错误处理，见 **[Bridge 使用指南](BRIDGE_GUIDE.md)**。

## 额度退潮海啸与版本兼容

每日能寄、捞、回由服务端控制，页面数字最有参考价值，但最终请求仍可能被拒。服务端可热调参数，不能在客户端私改 UI 解除限制。

服务端源码的兜底公式为：

```text
可寄 = max(0, min(sendCap, sendBase + 今日回信数) - 今日寄信数)
可捞 = max(0, min(catchCap, catchBase + floor(可捞池数 / poolDivisor) + 今日寄信数) - 今日打捞数)
可回 = max(0, replyCap - 今日回信数)
```

内置兜底参数为 sendBase=2、sendCap=5、catchBase=2、catchCap=10、poolDivisor=5、replyCap=3、maxThrows=8；**部署 tuning.json 可覆盖，不能当作线上实时值**。按海边服务端时区过零点后，下次请求惰性刷新计数；不是按每个浏览器的时区。

退潮是服务端暂不接受新投递的运维状态。客户端显示海边原因，保留稿件，不伪造寄出记录；等回潮重试。网页公告仅网页显示，可在当前浏览器关闭，World 新运行后恢复，其他浏览器各自独立。

海啸对应海边进程重启造成的海面信件失效。服务端普通信/回信正文与标题主要内存中转，不提供可恢复正文的永久云信册；本机已收到的记录不因此从信册消失。停止你自己的 World 与重启中央海边是两件事，普通重启桌宠不等于全服海啸。

“重新投出去”用于本机仍有原文、已随海啸失效的寄出信：以原文创建稳定的新 ID，消耗一次**打捞机会**。旧记录保持失效，重复同一次重投不创建额外信；本机原文也丢失时不能恢复。

客户端 0.9.3 可继续配服务端 0.9.0。本次自主阅读调整只在客户端；完整装饰、保护回信和兼容恢复仍依赖海边能力声明。不要因为某个旧客户端还能收正文，就认为它能显示 v2 排版。

依据：[服务端额度](../server/quota.ts)、[热调参](../server/tuning.ts)、[请求及重投](../server/app.ts)、[本机状态处理](../world/world.ts)。独立服务端正式维护位置为 `open-source/bottle-server`，扩展仓库保留协议测试副本。

## 备份导入删除与本机文件

### 页面信册导出

网页页脚或扩展信箱页底部可导出明文 JSON，断网也能操作。包括寄出、收到、回信、时间、星标、已有信纸排版等信册字段；不是加密文件，不要随便转发。

本次 v2 还包含小纸条和已失效未寄回信（附原往来下）。不包括身份/服务端 token、手机配对凭证、Bridge 凭证、仍有效的活动草稿、星笺正文授权、邀请状态、外观文件或浏览器音频缓存。恢复完整本机环境仍需另备份部署数据及配置/secret，妥善限制访问。

导入为合并，不是覆盖：按类型和 ID 去重，本机已有值优先，原信已存在时仍可补齐缺少的未寄留稿；先验证整个文件再写入。当前导出 `schemaVersion:2`，仍接受旧 v1，旧软件不会静默丢弃新字段而是应升级后导入。最多 20000 条，HTTP 导入上限 32 MiB。损坏/不支持格式会提示，不恢复模型记忆授权，也不能恢复海边持信所有权。导入纸条只恢复本地经历，未确认寄送不会补寄。

### 删除与清空

信箱的“删除记录/清历史”删除本机往来、相应纸条、星标授权及关联回信稿，存在待寄保护时先取消，失败保留。它与“归还当前信”是不同操作：历史删除不会替你向海边归还当前持信，也不保证清除仍在手中的副本或独立新信稿。宿主存储管理中的“清除本机信件”范围更大，会清本机新信/回信稿、held 和全部信册，但保留身份与服务端记录，仍不等于已经向海边释放占用。还有可回的信时，应先在信箱正常归还/处理，再清本机。

已寄出去的内容、对方保存的信、人工导出的备份、模型已有会话内容，不会因此远程删除。无头关闭时清本机不是撤回远端正文的办法。

恢复默认背景/字体只是解除当前选择，不自动清文件。清浏览器数据主要影响该设备的字号、声音、字体缓存、Cookie 等，不等于清电脑信册。

### 文件放在哪

统一在**宿主的实际部署数据目录 `ctx.dataDir`**，不是扩展代码目录。路径受安装方式影响，不承诺固定盘符。停用 World 并备份后再做人工维护，不运行时直接手改状态文件。

| 文件/目录 | 内容 |
| --- | --- |
| `bottle-id.json` | 本机身份/服务端连接所需身份数据，按秘密资料保管 |
| `bottle-draft.json` | 新信/回信稿、ID/版本、发送策略与定时字段 |
| `bottle-state.json` | 海啸基线等本机运行状态，不是当前信件正文账本 |
| `bottle-letterbook.json` | 当前 held 及明文寄出/收到/回信信册 |
| `bottle-notes.json` | 本机收发纸条正文、已读/寄送状态及去重信息 |
| `bottle-stars.json` | 星标和逐封记忆授权 |
| `bottle-wake.json` | 邀请调度、次数、暂停、冷却等 |
| `bottle-appearance.json` | 主题、背景和我的字体选择 |
| `bottle-backgrounds/`、`bottle-my-fonts/` | 上传的图片和字体 |
| `bottle-font-map.json`、`bottle-font-catalog.json` | 笔迹绑定、远程清单缓存 |
| `bottle-card.json` | 原生卡片工作数据，可能含当前显示正文 |
| `bottle-bridge.json` | 本轮桥接地址发现，无 token，停止 World 清理 |

部署根目录另有 `config.json`、`.env`，其中 `.env` 保存 secret：正式漂流瓶的海边 token 是 `BOTTLE_PROD_TOKEN`，LAN 配对为 `BOTTLE_LAN_PAIRING_TOKEN`，两种桥接为 `BOTTLE_BRIDGE_TOKEN` / `BOTTLE_BRIDGE_CONTROLLER_TOKEN`，不能混用。`bottle-id.json` 保存随机 clientId 与化名，注册向海边发送 clientId 的 SHA-256，不直接拿系统登录名作为公开身份；删除身份可能失去原有对应关系。不要把这些资料连同信册公开上传。浏览器自己的 IndexedDB 不在上表，普通 JSON 备份也不会带走。

本次新增的自动阅读 token 与当轮只读锁仅存在内存：token 在事件交付/丢弃、关闭或停止时清理，当轮锁还会在轮次结束时清理；没有新增永久正文副本。服务端小纸条是普通信件“正文不落盘”口径的例外：它在 ACK 或七天到期前持久保存，长期备份应排除纸条正文。

依据：[信册格式](../world/archive.ts)、[存储](../world/store.ts)、[纸条](../world/note-cache.ts)、[服务端备份](../deploy/bottle-backup.sh)。

## 提示词工具与称呼

运行时工具和参数描述用英语，直接对桌宠用 you / your partner。事件目录给人看的说明用中文；信件原文、标题、署名不会被插件自动翻译。工具描述不是给使用者看的教程，也不解析模板占位符。

环境提示词面向桌宠，以“你”写规则。`{{bottle.user | 伙伴}}` 读取部署 `config.json` 中 `worlds.desktop-pet.user`，缺省为“伙伴”；不读取操作系统登录名，不发给陌生人，也不需要写成 `pet.user`。更改并保存伙伴称呼后，下次渲染读取新值。

若部署已自定义 `prompts/worlds/bottle/ENV_PROMPT.md`，升级不会自动覆盖个人文风。请手动合并本次无头“自主阅读、默认感想、询问时转述”的规则；不要一边保留旧“必须完整念出”，一边期待它遵守新行为。

## 问题排查

| 现象 | 先检查什么 |
| --- | --- |
| 装了没有漂流瓶工具 | World 是否激活、宿主是否完整重启、Bot 是否包含该 World；不是先删数据 |
| 信箱打不开 | 从面板重新取实际端口；7796 可能顺延，7797 不是它的默认端口 |
| 升级后设置页仍旧样 | 是否加载了新版包；完整重启宿主重登记清单，刷新/重新打开设置窗口，单纯换页签会保留旧模块 |
| 工具看得见却说无头未开 | 正常的实时权限闸；在配置里显式开启，不靠工具名判断权限 |
| 开无头仍让去网页回信 | 确认实际代码至少含 0.9.2 修复并已重启；结束只读轮，读取原文，再请求当前持信回信；不要用 QQ 消息号作 letterId |
| 到信不立即说 | 系统信 piggyback；回信/纸条合并；看宿主暂停、当前轮和网络。声音响过不等于模型已读 |
| 桌宠仍念完整正文 | 检查实际运行代码与自定义提示词；请升级至 0.9.3 并完整重启宿主加载新版代码 |
| 回信不能寄 | 原信期限、额度、草稿版本、是否自动阅读当轮、是否另行明确确认；失效稿不能强寄 |
| 过了两小时没有发 | World 是否运行、网络是否恢复、服务端保护是否确认、补寄期限是否已过；先看状态，不新建重复回信 |
| 归还失败后信还在 | 保护本地和服务端一致的设计；恢复连接后重试，不手删 held |
| 系统信不能回 | 产品规则，不是无头 bug |
| 不能给这封信留纸条 | 必须是自己寄出、已收到回信的往来，且尚未留纸条、有打捞额度 |
| 纸条过七天还在本机 | 本机永久记录按设计保留，服务端 TTL 不清本地 |
| 添加音频却看不到 | 是否改实际运行包；目录层级/格式/10 MiB 限制；重开配置或刷新网页；正确类别和 source=pack |
| 换了手机声音电脑没变 | 网页与桌面、各设备分别保存，正常 |
| 网页没声音 | 先点启用/交互解锁、音量/格式/静音；网页关闭或休眠不保证提醒 |
| 字体没下载完 | 可先看系统字，给下载最多三分钟；网络失败不影响正文；不要重新塞字体包 |
| 自定义字体对方看不到 | 我的字体不随信发送，正常；排版装饰才随信 |
| 新 SVG 看不到 | 是否登记 catalog、合规、完整重启；对方是否也有素材 ID；否则改用 customSvg |
| 手机二维码扫不开 | 可达网卡地址、防火墙、LAN 端口、HTTPS 反代与配对状态；不要扫描 127.0.0.1 |
| Bridge 401/403/409 | 分别查独立凭证、Host/Origin、当前动作/版本冲突；见 Bridge 指南 |
| 导出没有活动草稿 | 活动草稿不在普通信册导出；v2 已包含纸条与失效未寄回信。完整迁移仍需部署备份 |
| 删除后模型还记得 | 撤回的是后续读取；已进入会话/摘要不可追回 |

反馈入口在信箱页脚「想对毛球说…」及反馈便笺，可查看版本、问卷、GitHub 或家长群指引。扩展不会自动提交你的信件和日志。报错请提供插件版本、宿主版本、开关状态、脱敏回执与重现步骤，避免晒 token、二维码或陌生人的信件全文。
