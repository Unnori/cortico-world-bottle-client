# 种子瓶（海边邮局）

> 这是 v0.1.0 的附加项，见设计稿 §13。主链路不依赖它；它解决的是「内测期池子太空，第一封信捞不到」。

真人写的信永远优先。只有池子里一封真人信都没有时，海边邮局才补位。

## 一个文件一封信

`seeds/*.json`，文件名随意（按名字排序读）。一个文件放一封信，或者放一个数组放多封。

```json
{
  "id": "seed_lighthouse",
  "body": "我在灯塔上值夜，一班四小时。……",
  "signature": "值夜的人",
  "topic": "灯塔"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `[A-Za-z0-9_-]`，1–64 字符。**改名等于一封新信**：见过旧 id 的人会再见到一次。 |
| `body` | 是 | 正文，最多 400 字。比 Coo 的 120 字宽，因为这是手写的。 |
| `signature` | 否 | 落款，最多 40 字。显示在正文下面，不替代「海边邮局」这个来源。 |
| `topic` | 否 | 一行小标签，最多 20 字。 |

## 三条规矩

1. **每人对每封最多一次。** 同一封信可以被所有人捞到，但不是全局一次性——8–12 封能服务任意多人。
2. **每人最多捞到 2 封**（`BOTTLE_SEEDS_PER_USER_MAX`）。否则新人第一天就把所有种子捞完，第二天又空了。
3. **种子消耗捞取配额**，规则与真信一致，不做特例。

## 它不回信

海边邮局不回信（§13.7）。页面和卡片会写明「它不会回信」，也不给「回信」按钮——留一个点了石沉大海的按钮等于骗人类。

## 改完怎么生效

**不用重启进程。** 重启会海啸（正文只在内存，见 §5.1）。

- 服务端 `fs.watch` 盯着这个目录，改完即校验并热载；另有 30 秒轮询兜底。
- 生产环境用私有 git 仓库同步，systemd timer 每 5 分钟 `git pull`（见 `deploy/`）。**不要用 rsync**：手滑删文件服务器上也就没了，git 有历史和回滚。
- 校验失败不阻塞：坏文件跳过并保留上一版，其余照常加载。

## 只加不改

修改已有的种子，会让**已经见过它的人**看到不同内容。可以改，但要接受这个语义。建议只加新文件。

## 运维探针

```bash
curl http://127.0.0.1:8787/health
```

`seeds.generation` 变了 = 内容热载成功；`startedAt` 没变 = 进程没重启。

## 写这些信的时候

**种子信是人类对这个世界的第一印象。** 第一批人捞到的第一封信如果是敷衍的，就不会捞第二次。

现有 12 封是照着这个写的：具体、克制、不劝人、不给建议。别加「一切都会好的」。
