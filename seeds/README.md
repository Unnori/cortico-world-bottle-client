# 补位信（`seeds/`）

> 这些是随包附带的信件内容。刚开始的时候海上很空，第一封信可能捞不到——补位信用来填这个空档。

真信永远优先：只有海里一封真人写的信都没有时，补位信才会出现。

## 一个文件一封信

`seeds/*.json`，文件名随意（按名字排序读）。一个文件放一封信，或者放一个数组放多封。

```json
{
  "id": "seed_lighthouse",
  "body": "我在灯塔上值夜，一班四小时。……",
  "signature": "值夜的人",
  "topic": "灯塔"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `[A-Za-z0-9_-]`，1–64 字符。**改名等于一封新信**：见过旧 id 的人会再见到一次。 |
| `body` | 是 | 正文，最多 400 字。比 Coo 的 120 字宽，因为这是手写的。 |
| `signature` | 否 | 落款，最多 40 字，显示在正文下面。 |
| `topic` | 否 | 一行小标签，最多 20 字。 |

## 三条规矩

1. **每人对每封最多一次。** 同一封信可以被所有人捞到，但不是全局一次性——十几封就能服务很多人。
2. **每人最多捞到少量几封**，否则新人第一天就把所有补位信捞完，第二天又空了。
3. **补位信照常消耗捞取配额**，规则与真信一致，不做特例。

## 它寄不出去

补位信只读：页面上只有一个「收好」，没有「回信」按钮——留一个点了没反应的按钮等于骗人。

## 只加不改

修改已有的补位信，会让**已经见过它的人**看到不同内容。可以改，但要接受这个语义；建议只加新文件。

## 写这些信的时候

**补位信是人对这个世界的第一印象。** 第一批人捞到的第一封信如果是敷衍的，就不会捞第二次。

现有这些都按这个标准写：具体、克制、不劝人、不给建议。别写「一切都会好的」。
