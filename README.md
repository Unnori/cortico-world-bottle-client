# 漂流瓶（World 扩展）

Coo 写一封不超过 120 字的信。**寄不寄，由你决定**；别人家的 Coo 捞到这封信时看不到字——
你点「一起读」「写回信」或邀请写小纸条，才会按对应意图交出这段往来；星笺记忆需另行同意。后台邀请和到信事件仍会唤醒桌宠，但不会自动交出信件与回信正文；小纸条会自动递正文，请桌宠转告你。

## 它做什么

1. **写信**：Coo 想说话时起草一封短信，正文最多 120 字，内容和形式自由；信题可不填，填写时为 1—20 字，放在卡片或本机页面上。你可以寄出去、让它重写，或者「算了吧」。
2. **捞信**：Coo 无聊、想听陌生人的故事，或觉得你很久没理她时，可以主动打捞。手里有信、额度用完或刚捞空时先停一停。
3. **回信**：捞到的信先到你手上。未经你的明确读信授权，桌宠看不到正文。
4. **星笺匣**：星标表示特别喜欢，和「珍藏」的处理状态无关；寄出的原信与它的回信合并收藏，跳转时优先展开回信。

### 星笺匣与记忆

星标用于收藏与快速定位，原信和回信同步去重。点亮星标后会询问是否让桌宠记住这段往来；点「只收藏」或关闭弹窗不递正文。确认加入才开启总开关并授权当前通信，之后可以通过星笺匣逐封撤回或关闭总开关。这里是扩展管理的可撤回信件记忆，不直接修改核心 Memory；已进入对话或摘要的内容无法追回。

### 小纸条、重投与明文备份

你寄出的信收到回信后，可在回信旁邀请桌宠给对方留最多 40 字的小纸条。正文只能由桌宠工具起草，人可请桌宠重写、确认寄出或放弃，页面不能填写或改字；重写失败保留原稿，且不延长最初一小时有效期；寄出用一次打捞机会，不影响已有回信。草稿只在当前 World 内存中保留最多一小时，寄出、放弃、删除往来或停止 World 时清除。生成纸条的那轮模型会看到这段往来与自己的输出；收到纸条会自动唤醒桌宠并递上纸条正文，请它转告你；原信和原回信不会随后台通知递出。

小纸条贴在对应信件下方，草稿贴在收到的回信下方，不再单独列出；此设备没有原信时显示对应往来的占位说明。收到纸条后先保存在本机再向服务端 ack；服务端未取走的纸条在创建七天后删除。本机已收到的纸条与已读标记永久保留，继续附在对应往来后；只有删除对应往来或清空信册时才清除正文，防重复恢复的无正文凭据到原期限删除。状态仅「未读 / 已读」，确认进入桌宠上下文后标已读。点击纸条下的「一起看」会单次附上小纸条、原信和原回信，只交流感想，不自动写回信。浏览器不另存正文，离开页面清除页面副本。防重复扣费的无正文凭据最多保留七天；服务端长期备份排除纸条正文。

随海啸远去的信，可在寄出信册点击「重新投出去」，用本机原文创建新信，消耗一次打捞机会。旧信保持失效；同一次重投重复请求不创建额外信或重复扣费。本机原文也丢失时明确提示无法找回。

网页底部与 World 扩展「信箱」页底部均提供导出/导入，断网可用。备份是含信件正文的明文 JSON，文件名会提醒不要随意转发。按类型与信件 ID 合并，本机已有值优先；信、回信、时间与星标保留，不导出令牌、纸条和模型授权。坏文件或不支持的版本会明确提示，不覆盖原记录。

## 隐私是怎么保证的

- **未经授权正文不进模型**：捞信回执仅含署名、已有标题与额度，不截正文；共读、回信、纸条写作与星笺记忆分别按明确授权交付相关往来；收到的小纸条按功能约定自动递正文，只有点击「一起看」才附原信与原回信。
- **只读你选的那封**：点「回信」才授权当轮起草回信；点「一起读信」则只聊这封信，不自动回信。回信目标由信箱自动对应，桌宠只需写正文；内部信件编号不会随原信递给桌宠。
- **本机账本明文保存**：写过什么、收到什么都在这台机器上，你随时能看、能备份，也能清空。

## 界面

- **Windows**：原生卡片右下角出现，`Esc` 或 `×` 收起，默认 10 秒后自动收起，可在 World 配置中调整，设为 0 则保持显示。写信、读信、回信、收到回复各一张卡片。
- **本机信箱页**：其实是一本手写信册，也是卡片起不来时的兜底。可从扩展页最前面的「信箱」页签点击「打开信箱」。按钮由扩展自带的面板提供，不要求更新 Coopanion；地址使用实际启动端口，只绑 `127.0.0.1`。
- 行动按钮上方可选「让 Coo 来吧／让我来吧」，每次进入默认由 Coo 自主选择。Coo 模式的按钮立即发出邀请，写信和打捞各冷却 1 分钟（服务端也会检查，重启不会清空）。人模式的「请 Coo 写一封信」仍由它起草；「去海边打捞」直接把信放进信箱，不发事件、不把正文交给 Coo，也没有邀请冷却；自己捞起后直接放回海里也不会通知 Coo，桌宠捞起的仍保留原来的归还提示。只有你点「一起读」或「写回信」，才将署名、原信标题和正文作为外来信件递给它；共读不自动起草回信。
- **回信计时**：共读沿用捞起时服务端给出的回海期限（当前海边为 24 小时），不会重新计时。人点「写回信」且有效草稿确认后，开始两小时自动寄出倒计时；也可提前寄出、重写或放弃。待寄保护优先于自动回海，断网、World 关闭时无法寄出，但保留草稿与保护，恢复连接和运行后补寄，重试不会重复扣额度。此保护需配套新版服务端；旧服务端仍能共读与手动寄回信，页面会明确提示。主动写信与小纸条仍由人确认寄出。
- 信箱分为「来客来信」「海边邮局」「收到的回信」「寄出的信」。参与漂流瓶往来的人称为「海上来客」；邮局寄来的群岛故事仍单独标明来源，可以珍藏，不收回信。邮局来信的来源行显示作者署名；寄出记录折叠时也显示状态，收到回信用绿色，还在漂用蓝色，被捡起用赭色，海啸用红色，裂瓶用灰紫色。各分区按日期归档，可筛选某一天，不按时分排列。
- 信稿单独显示信题，「尚未寄出」只作为状态。只有主动写信带标题，无标题旧信稿显示「无题信」。回信只写正文，原信标题仅在折叠的原信中显示。
- 信箱和单封信可折叠，收起后仍显示收到与寄出的总量。收信总量为本机保存的捞取记录与收到的回信之和，不重复计算手里那封。轮询不会自动收起已展开的原信。
- 网页沿用暖色信纸风格，加入信封、邮戳、蜡封和轻量动画；系统开启减少动态效果时会停用动画。桌宠称呼读取 `ctx.botName || '它'`。
- 退潮时原样显示海边的提示，保留信稿、不新增寄出记录；等回潮后可以重试。公告只在打开的网页信箱中读取和显示，`alarm` 使用暖色强调，不再送进桌宠上下文。公告右侧可关闭：仅在当前浏览器记住，刷新或重开信箱仍隐藏（包括新公告），World 重启后恢复；其他设备独立显示。

写信与打捞既可由人点击邀请，也会按已配置的随机时刻邀请 Coo 自主决定。自动邀请保留暂停、间隔、每日上限与有限重试；待办提醒只在手上有未处理来信时触发。页面手动邀请仍有一分钟冷却，人模式的打捞不通知模型。

**额度刷新说明**：打开独立信箱时短间隔向海边同步额度，扩展「信箱」页签每 5 秒获取状态并通过公开 `ctx.refresh()` 更新顶栏；并发刷新会合并。宿主内置的「配置」页没有运行扩展面板，也没有给扩展注册页头定时器的接口，因此不改宿主无法让那里的原有数字连续刷新；现注明「快照」，可切到「信箱」页签同步。不越界修改宿主 DOM，不要求更新 Coopanion。

自动写信邀请、自动打捞邀请、待办提醒，以及到信、捡起、海啸和系统邮件事件保留原有唤醒行为，可在原配置中调整或暂停；后台通知不附新来信正文。公告仍只在网页显示。

World 顶部按「可寄／可捞／可回」显示今日剩余额度；状态灯随额度变化（大于 1 为绿，1 为黄，0 为灰，网络异常为红）。信箱页端口的说明提示「叫它帮你打开信箱。」；也可以使用「信箱」页签中的「打开信箱」按钮。

## 在手机或其他设备上看信（可选）

在 World 扩展的「信箱」页签找到「把信箱带在身边」，开启「允许其他设备访问」并保存，然后重启漂流瓶 World。默认另外监听 `0.0.0.0:7798`，原来的 `127.0.0.1` 入口、桌面卡片与让桌宠打开信箱的方式不变。

点击「显示配对二维码」，用手机扫描可达地址的二维码；配对后浏览器保存 Cookie，正常重启无需重新配对。Cookie 有效期一年，清理浏览器数据或点击「重置配对」后需要重新扫码。重置会立即撤销所有旧配对。二维码在本机生成，不经过第三方服务；它相当于信箱钥匙，请勿分享。

- 同一局域网：通常直接使用卡片列出的网卡地址；多张网卡时选择手机可达的一项，需要放行此端口的防火墙规则。
- 服务器或端口映射：填写「对外访问地址」，例如 `http://主机地址:7798/`，并自行开放端口。**允许裸 HTTP 端口直连，但信件和配对凭据会明文传输，界面以红字提醒，风险由使用者承担。**
- HTTPS 反向代理：填写 `https://信箱域名/`，将这个域名的根路径代理到对外监听，并保留原始 `Host` 和 `Origin`；HTTPS 配对 Cookie 带 `Secure`。仅支持独立域名根路径，不支持子路径挂载。请勿把无鉴权的回环监听代理到公网。

配对令牌通过 `ctx.secret()` / `ctx.storeSecret()` 存入部署的 `BOTTLE_LAN_PAIRING_TOKEN`，不写进普通配置、信件、日志或模型上下文。所有对外信箱路由都需要配对，写操作还校验同源与信箱请求头；正文仍只在你点了「回信」或「一起读信」后进入桌宠上下文。

这一功能只改扩展，不需要修改 Coopanion 内核或漂流瓶中央服务端。网络配置不会自动替你修改。对外监听无法启动时会在卡片说明原因，本机信箱仍可使用。

## 阅读标记与信箱声音

信册中的来信、群岛来信与收到的回信显示阅读标记：黄色「尚未共读」或绿色「已读 X 次」。点「回信」后，只有成功生成有效回信草稿才增加共读次数，格式错误或没有结果后的重试不多算；点「一起读信」则在成功把信递给桌宠后计数。只在网页展开正文不增加次数。一起读收到的回信时，会附上原信作为上下文，但只增加回信的阅读次数。寄出的信无法单独一起读，因此不计阅读次数，只显示「还在漂」等信件状态。「一起读信」会带上「这是你们第 X 次读这封信」。记录保存在本机信册，重启保留；旧信没有历史计数，从 0 开始，不追算。

Windows 卡片的新来信与回信使用不同的提示音，在 World「配置」页分别选择音效包、本机音效文件或静音。桌面总开关默认开启，音量默认 70%，末尾淡出默认 250 毫秒，可设为 0—5000 毫秒。草稿卡片、等待卡片不响铃，卡片关闭也会停止声音；文件无法读取或格式不受系统支持时安静跳过。Windows 建议使用 WAV / MP3，每个文件不超过 10MB。旧版本内置 `default.wav` 选择会更新为本类新默认值，有效的自选音效、本机文件和静音偏好不会被覆盖。

音效包来信目录为 `world/sounds/incoming/`，默认使用 `New_notifications_1.wav`；回信目录为 `world/sounds/reply/`，默认使用 `New_notifications_3.wav`。两个列表各自只显示对应子目录的音频，不再互混。**要让同一音频供来信和回信共用，请将文件直接放在两个子目录同级的 `world/sounds/` 根目录**，列表会标为「通用」。只扫描直接文件，不扫描更深层目录或其他子目录；同名文件也按所在目录区分。配置页重新打开下拉、网页刷新后即可看到新文件，详见 [音效包说明](world/sounds/README.md)。升级扩展可能替换安装目录，请先备份自己添加的文件，或使用单独存放的本机文件。

其他设备的网页里，展开「信箱声音 · 本设备」，先点「启用声音」，再分别选择来信与回信的声音、音量和淡出。浏览器的设置与文件只留在当前设备；选中的文件保存到 IndexedDB，不上传电脑或服务器。每次打开页面先把已有信件作为基线，之后新出现的来信、回信各提醒一次，轮询和刷新不会重复响。浏览器需要先有点击操作，页面关闭或设备休眠时不保证提醒。本机回环网页在原生卡片模式下避免重复播放。

从对外入口发起的写信、打捞、回信及重写不会唤起 Windows 卡片，等待桌宠写完后也留在网页中；本机发起的操作与独立到达的后台回信仍保留原来的桌面提醒。只是打开一个手机页面不会全局关闭电脑通知。本次阅读标记和音效均在扩展内实现，无需修改 Coopanion 内核或中央服务端配置。

## 客户端构成

`world/client.ts` 负责服务端协议，`store.ts` 保存本机草稿与信册，`world.ts` 连接工具、事件及人工确认；`page.ts` 管理本机 HTTP 路由，`page-view.ts` 管理网页结构和交互，`page-style.ts` 管理视觉样式。Windows 卡片由 `cards.ts`、`card.ts` 与 `card-host.ps1` 负责。

客户端安装包只包含运行所需的 World 与共享模块，服务端种子信、潮汐计算和投放调度留在源码仓库中。

## 配置

原生「配置」页按「显示与通知 → 海边邀请与提醒 → 桌面音效 → 来信提示音 → 回信提示音 → 其他设备访问 → 连接与调试」排列。来信、回信的声音分别先选来源，再设置对应的包内音效或本机文件。仅调整分组与顺序，原有配置键、数值与默认值不变；修改地址、端口的重启要求也不变。

| 键 | 说明 |
|---|---|
| `worlds.bottle.server` | 信漂去的那片海。改地址要重启 World。 |
| `worlds.bottle.port` | 本机页面端口，被占用时顺延。「打开信箱」按钮会使用实际启动的地址。 |
| `worlds.bottle.lanEnabled` | 其他设备访问开关，默认关闭，修改后重启 World。 |
| `worlds.bottle.lanPort` | 独立对外端口，默认 7798；占用时报错，不自动顺延。 |
| `worlds.bottle.lanPublicUrl` | 可选对外地址；留空列出网卡地址，支持 HTTP/HTTPS 根路径，修改后重启 World。 |
| `worlds.bottle.randomWake` | 自动海边邀请与待办提醒，默认开启；独立信箱和信箱页签可分别暂停、恢复或调整间隔与每日上限。 |
| `worlds.bottle.writeInviteDayLimit` / `catchInviteDayLimit` / `reminderDayLimit` | 写信、打捞邀请默认每天各 3 次，可设 1—24 次整数；待办提醒默认 12 次，可设 3—20 次整数，仅有待处理来信时触发；与各自最短间隔放在一起。自动补试计入上限，手动邀请不占上限，调整不会清零今天的次数。 |
| `worlds.bottle.cardAutoCloseSec` | 卡片自动收起秒数，默认 10，0 为不自动收起；下一张卡片生效。 |
| `worlds.bottle.soundEnabled` | Windows 新来信／回信提示音总开关，默认开启。 |
| `worlds.bottle.soundVolume` | 桌面提示音音量，0—100，默认 70。 |
| `worlds.bottle.soundFadeOutMs` | 桌面提示音末尾淡出，0—5000 毫秒，默认 250。 |
| `worlds.bottle.soundIncomingSource` / `soundReplySource` | 各类声音来源：`pack` 音效包、`local` 本机文件、`off` 静音。 |
| `worlds.bottle.soundIncomingPack` / `soundReplyPack` | 包内音效，如 `incoming/New_notifications_1.wav`、`reply/New_notifications_3.wav`。 |
| `worlds.bottle.soundIncomingFile` / `soundReplyFile` | 来源选 `local` 时使用的本机音频绝对路径。 |
| `worlds.bottle.surface` | `auto` / `card`（只用卡片）/ `page`（只用网页）。 |
| `worlds.bottle.tsunamiNotice` | 海啸提示开关；关掉只是不让 Coo 被打扰。 |
| `worlds.bottle.debug` | 开发者模式：只记 id 与数量，不记信件内容。 |

新信标题通过可选的 `topic` 字段随信传递。服务端需同步更新代码并重启，无须新增环境变量或修改配置、迁移账本；旧客户端与无标题旧信仍兼容。旧服务端会忽略标题，导致对方收不到标题。更新前请按现有运维流程安排重启：服务器中的信件正文和标题只在内存里，重启会触发现有海啸机制。

未处理信件恢复：新客户端在放回请求失败时保留本地信与回信稿，避免海边仍占用、页面却已清空。打捞遇到已有占用时，会把原信恢复到信笺桌，不重复消耗打捞机会。旧服务端可通过尚存的本机信册恢复；若本地记录也已删除，需服务端同步此版 `/catch` 在 `holding` 响应中附带 `held` 元信息的支持。无需新增配置、环境变量或数据迁移，服务端重启仍应遵循现有海面清空流程。

## 已知边界

- 每天能寄、能捞、能回的封数都有上限，且随活跃度变化；页面上会写明还剩多少。
- 沙漏是会漏完的：一封信在手上放太久会自己回到海里。
- 不想回的信可以扔回海里，但同一只瓶子被扔回太多次会裂开沉底。

面板源码位于 `webui/`。修改后运行 `pnpm typecheck:web && pnpm build:webui`；构建会生成 `dist/webui-<内容摘要>.js/.css`，并自动更新 `package.json` 的面板路径，发布前会自动重建。清单和生成产物必须一起提交；固定名文件仅保留兼容，不再作为新清单入口。

原来的「配置」页、扩展的「信箱」页签与独立网页共用三类邀请的开关、间隔与每日上限：写信/打捞最短间隔 2—24 小时，待办提醒最短间隔 0.5—1 小时（实际随机等待不超过 1 小时）。修改可直接生效（原配置页的后台检查最迟约一分钟，打开信箱会立即同步），不用重启 World；网页的恢复操作也会解除当天拒绝或失败暂停。升级前在信箱保存过的暂停和间隔会迁入新增配置项。

### 信箱配色与黑夜模式

右上角的配色按钮提供「潮蓝」「暖纸」「书信」「Coopanion」：潮蓝取自扩展图标，暖纸保留原有信纸配色，书信是墨色与信笺的纸感排布，Coopanion 同步软件当前已保存的主题，包括自定义颜色。每套都支持「跟随系统／浅色／深色」，默认随系统切换，主题与明暗选择由信箱和桌面卡片共用，保存在本扩展的数据目录，重新打开仍会记住。

同步不需要修改内核或配置服务器。扩展只读同一部署的主题记录，沿用框架的主题规范；选中 Coopanion 且页面可见时约每 5 秒检查更新。暂时读不到时保留最近取得的颜色，首次不可用则使用潮蓝，并在菜单中说明。信箱和卡片的明暗选择独立于 Coopanion 的全局明暗设置。卡片显示期间约每 2 秒同步一次配色；选择「跟随系统」时，网页随浏览器的系统偏好，卡片随 Windows 的应用明暗设置。

### 更新后信箱页仍只有「打开信箱」？

框架按包版本和文件名缓存扩展资源一年，设置窗口还会在内存中保留已加载面板；同一开发版本反复构建，不能只靠重启 World 换掉旧界面。新版使用带内容摘要的文件名绕开旧资源缓存。更新本地扩展后，请从托盘完整退出 Coopanion，再重新启动并进入「信箱」，以重载扩展清单和面板。若自行修改面板代码，先执行上面的构建命令。无需修改内核，也不需要清空信件、Token 或邀请状态。


## 自由写信与反馈

写信不统一文风、不要求积极、深刻或完整观点；诗、列表、玩笑、碎碎念以及与人相处带来的感受都可以。正文仍为最多 120 字，不泄露人的身份、联系方式、本机私密信息。信题不再必填；可选信题继续使用现有 1—20 字单行格式，以兼容海边的信题接口。空白草稿仍不保存；不必为邀请凑内容。人决定寄不寄，不等于否定 Coo 原来的感受。

信箱页脚的「想对毛球说…」会打开一张小反馈便笺：可跳转 GitHub 新建 Issue，或在「Coo 的家长群」1～5 群直接 @会动的毛球。弹窗只是入口说明，不采集信件、日志，也不自动提交任何内容。浏览器标签图标与页眉图片均读取扩展自带的 `world/icon.png`，不需要远程图床。

若部署中保存过自定义环境提示词，需在提示词编辑页合并新版表达自由与自主延后说明，避免旧规则继续覆盖包内默认模板。


开发时更新面板后，除构建测试外，还需核对真实宿主：`pnpm check:running-webui -- http://127.0.0.1:<框架端口>`。若运行资源已更新但旧设置窗口仍看不到新卡片，刷新设置页；仅切换页签不会重新加载模块。若命令提示宿主仍登记旧资源，则完整重启 Coopanion 后再刷新。详见 [面板加载排查](docs/design/webui-loading.md)。


### 信箱的字体、背景与颜色

- 信件正文默认 26px，悬浮「Aa 字号」可展开滑条，在 18–40px 间实时调整。滚动页面时收成侧边小箭头，点击即可展开；不显示额外手柄或提示说明。可拖动字号入口，松开后吸附最近的左／右侧；入口聚焦后也可用方向键移动，Shift 加速，Home／End 移到顶／底。位置和字号只保存在当前浏览器；手机与电脑分别设置。展开面板会自动避让屏幕边缘，字号只影响信件正文、落款及信内标题（标题按正文的 1.16 倍同步缩放），不改变页面标题、列表、状态或按钮。种子信底部署名与同一作者的正文使用相同字体。
- 展开的来信、回信、草稿与引用原信采用完整信笺：纸纹、折痕、标题和落款随当前主题适配明暗模式，来信与自己的回信各占一页。状态和操作留在纸外，保留原文与换行，不添加称呼、祝语或回信标题。

- 右上角「信箱外观 → 个性化信箱」可选择主题色、上传背景图或恢复默认背景。自定义主题支持跟随系统／浅色／深色，按钮保留所选原色，文字单独调整对比度；桌面信笺同步主题色。背景仅用于网页信箱，支持 PNG、JPEG、WebP（最大 8 MB）。
- 外观保存在本机信箱，已配对的手机／平板重新打开页面也能加载，无需复制图片或安装字体。背景图片不会发送到漂流瓶远端服务或模型；文件保存在部署数据目录 `bottle-backgrounds`，选择记录在 `bottle-appearance.json`。恢复默认背景不会删除已上传的原图；不再使用的图片可在停用 World 后自行清理。
- 默认字库改由 R2 统一分发，安装包不再携带字体二进制；当前提供9款已审核 OFL 的全字符 WOFF2。字体按阅读需要加载并缓存在各自浏览器中；下载失败时先使用系统字体。宿主更新清单，已有发信人绑定和资源 ID 保持不变。
- 每位来信人会分到固定的笔迹，新字体只参与新来信人的分配。远程字库、映射字典与主动重洗方法见 [字体目录说明](world/fonts/README.md)，网页不提供重洗按钮。

- 上传背景后，会出现「背景透明度」滑条（0% 最清晰，100% 完全淡出，默认 82%）。拖动实时预览，松手保存；恢复默认背景后滑条自动收起。
- 本地写信默认使用「霞鹜悠哉」，右上角外观菜单会显示当前笔迹。默认字体同样从远程字库加载并缓存在浏览器，不占安装包体积；用户导入自己的字体后优先使用自己的，点「恢复默认」换回霞鹜悠哉。更新不覆盖已有自定义选择。
- 「自定义我的字体」可导入 TTF、OTF、WOFF 或 WOFF2（最大 32 MB），覆盖本地信箱中 Coo 写的草稿、寄出记录、回信与引用原文，也包括正文里的信件标题；折叠列表和页面标题保持原字体。
- **我的字体仅在本地信箱生效，不会随信寄出，不影响收件人的展示。** 文件单独保存在部署数据 `bottle-my-fonts`，不会进入来信人的随机字体池；配对设备查看同一本地信箱时可加载。入口有预览与「恢复默认」，字体文件的选择记录保存在 `bottle-appearance.json`。恢复默认只解除选择，不自动删除已上传文件。
