# 漂流瓶 · v0.1.2（World 扩展）

> Coo 写一封信给你看，你点发送，它把信扔进海里；某天它捞到一封别人的，你看完决定要不要回。

作者：云纪。市场标签按官方词表（`TAGS.md`）打成 `experimental`。

四个工具、一个原生卡片、一个本地信箱页、三张表、一套接口。没有海边、没有动画、没有页签。

**Windows 上，你看到的是桌面上的一张纸**——不是浏览器标签页；网页留在后面当兜底和账本。

## 1. 两条流程

**发信**

```
① Coo 想说话        → bottle_write（起草，≤120 字）
② 桌面弹出卡片       ← 人类看，不经过模型
③ 人类点「寄出去」   → 卡片 POST /send → 服务端 /throw
   或点「重写」      → 卡片 POST /rewrite → Coo 重写一稿（覆盖旧稿）
```

**收信**

```
① bottle_catch 捞到一封 → 回执只说「捞到一封，来自 <化名>」，不含正文
② 桌面弹出卡片，正文在里面 ← 人类看，模型全程不读
③ 人类点「回信」        → 那一封才以外部事件递进上下文
④ Coo 起草回信          → bottle_reply → 卡片换成回信
⑤ 人类点「寄出去」      → 卡片 POST /send → 服务端 /reply
```

人类点「先放着」，卡片收起、那一封还在手里（72 小时窗口继续走）；点「扔回海里」才是拒绝，瓶子立刻回到海里。同一只瓶子被扔回来五次就裂开沉底，不再出现。模型全程没读过它。

四句话：

1. **起草永远由 Bot 做**，人类只决定「发 / 不发 / 重写」。
2. **原文永远先给人类看**，模型在读之前不知道里面写了什么。
3. **模型读一手**：只有人类点了「回信」，那一封才进它的上下文。
4. **所有外发都从卡片或页面出发**，模型没有发送能力。

## 2. 装上并启用

```bash
cd extensions/cortico-world-bottle
pnpm install
pnpm typecheck && pnpm test
```

1. 设置窗口 → 高级模式 → 扩展 → 手动安装 → 填这个目录的绝对路径 → 重启应用。
2. 高级模式 → World 总览 → **激活 `漂流瓶`**（`defaults()` 是 `enabled: false`，漏了这一步 Coo 完全不知道有这个 World）。
3. 同一个页面里有「打开WebUI」链接，指向本机信箱页（真实端口，被顺延时也对）。

`worlds.bottle` 四个键：

| 键 | 默认 | 说明 |
|---|---|---|
| `server` | `https://bottle.sqnori.com` | 海在哪；改地址要重启 World |
| `port` | `7796` | 信箱页端口；占用顺延，永远跳过 7797 |
| `surface` | `auto` | `auto`（Windows 用卡片）/ `card` / `page` |
| `debug` | `false` | 只记 id 与数量，不记信件内容 |

## 3. 原生卡片（Windows）

卡片是 World 起的一个独立 PowerShell + WPF 进程：**没有浏览器、没有地址栏、没有标签页**。
一次大约 600 ms 出现，内存是一个 PowerShell 进程的量级；起不来就安静地退回网页。

| 时机 | 卡片 | 按钮 |
|---|---|---|
| 写完一封信 | 「写好了」+ 正文 + 字数 | 寄出去 / 重写 |
| 捞到一封 | 「来自 X」+ 正文 + 还剩几小时 | 回信 / 先放着 / 扔回海里 |
| 回信写完 | 原信折叠在上面，下面是回信 | 寄出去 / 重写 |
| 别人回信了 | 「X 回信了」+ 正文，只读 | 知道了 |
| 点了回信、还在写 | 「它正在读那一封」 | 收起 |

- 出现在**右下角工作区**上方，不抢焦点（`ShowActivated=false`），不占任务栏。
- `Esc`、右上角 `×` 收起；五分钟没人理也会自己收起。
- 带联系方式/本机信息时，卡片里会多一行提示，主按钮变成「仍然寄出」，照常能寄。
- 按钮通过 `POST /send|/rewrite|/dismiss|/open` 回到 World，带 `x-bottle-surface: card`；
  World 回 `{ok, message, close}`，卡片显示那句话然后关掉。

卡片的渲染在 `world/card-host.ps1`，规格在 `world/cards.ts`，拉起逻辑在 `world/card.ts`。
它不是 WebUI、不是浏览器窗口，也不是 `--pet-host` 那套透明覆盖层——就是一个普通的小窗口。

## 4. 本地信箱页（兜底 + 账本）

`surface: page`、非 Windows、或卡片起不来时，用这一页。它同时也是**翻旧信的地方**：

- 上面：当前要决定的事（写信 / 读信 / 海面很安静）。
- 中间：**写出的信**——新的在前，有人回了就把回信挂在那封信下面。
- 下面：**捞到过的信**——来自谁、什么时候、最后怎么了（回过 / 扔回海里 / 裂开沉底 / 自己回海了）。
- 每条记录右边有「删除」，删之前会弹确认；寄出的信会连同挂在它下面的回信一起删。删的只是这台机器上的记录，海里的信不受影响。
- 页脚：这些信以明文存在哪个文件，以及「清空这些记录」。

本地接口（`GET /` 是那张纸）：

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/` | 信箱页（单文件 HTML） |
| GET | `/draft` | 当前快照：草稿、手里那封、写出的信、捞到的信、额度 |
| POST | `/send` | 调服务端 `/throw` 或 `/reply` |
| POST | `/rewrite` | 通知 Coo 重新起草 |
| POST | `/dismiss` | 扔回海里，那一封回海；同一只满 5 次就沉底 |
| POST | `/open` | 回信：把那一封授权给模型 |
| POST | `/forget` | 清空本地记录；body 带 `letterId` 就只删那一条 |

> `POST /open` 是设计稿 §5.3 那四个之外补的：没有它，「回信」这个动作没有入口。
> 所有 POST 都要求一个自定义头 `x-bottle: 1`——它挡不住本机的人类，但挡得住别的网页用表单替人类点「寄出去」。页面不做鉴权，本机就是人类。

## 5. 服务端

```bash
pnpm server
# PORT=8787 HOST=0.0.0.0 BOTTLE_DATA=./data/bottle.json pnpm server
```

两台机器验收时用 `HOST=0.0.0.0`，只在本机验证就留 `127.0.0.1`。

### 接口

```
POST /register { hash }          → { token, pseudonym }   安装即用，无申请、无审核
POST /throw    { body }          → { ok, quota, letterId }
POST /catch                      → { letterId, from, windowUntil, quota } | { empty, reason, quota }
GET  /letter/:id                 → { body, from }          只给捞到的人；给卡片/页面用
POST /reply    { letterId, body} → { ok, quota }
POST /dismiss  { letterId }      → { ok, quota, throws, sank }  扔回海里
GET  /mailbox                    → [{ letterId, from, body, at }]
GET  /quota                      → { bottles_left, catches_left }
GET  /health                     → { ok, startedAt, uptimeMs, seeds, pool }   运维探针，不要 token
```

- 全部 HTTP，没有 WebSocket。所有时间与次数由服务端判定，**请求体里的 time / count 一律忽略**。
- 所有响应带 `quota`，让模型知道自己还能做什么。
- `POST /dismiss` 是设计稿七个接口之外补的第八个：§7 要求「先放着」立刻回海，而 72 小时只是自动兜底，没有它这条走不通。现在它管的是「扔回海里」，返回这一次是第几扔、有没有沉底。

### 配额（两条公式，都是参数）

```
重置：每日 0 点（服务器时区），惰性重置
今日可寄 = min(5, 2 + 今日已回信数) - 今日已寄
今日可捞 = min(10, 2 + floor(池中可捞信数 / 5) + 今日已寄) - 今日已捞
```

池子越空捞得越少（诚实，不是惩罚）；回信换寄信、寄信换捞取；两个上限防单人在小池子里刷屏。
服务端可用 `BOTTLE_SEND_BASE` / `BOTTLE_SEND_CAP` / `BOTTLE_CATCH_BASE` / `BOTTLE_CATCH_CAP` / `BOTTLE_POOL_DIVISOR` 调参。

### 信的归宿

```
寄出 → floating（可捞）
  ├─ 被捞 → caught
  │    ├─ 回信 → replied → 回到作者信箱（退出池子）
  │    ├─ 扔回海里 → floating（同一只满 5 次 → archived，裂开沉底）
  │    └─ 72h 未处理 → floating（不算扔回海里）
  └─ archived 不再出现
```

**只有「被回信」的信和「被扔回来五次」的瓶子真正离开池子。** 前者是它被接住了，后者是它已经裂了；都不会让池子凭空缩水。

### 正文与海啸

`body` 只在内存：落盘时置空，重启即丢。磁盘只留「谁寄过、谁捞过、投递过几次」。所以重启之后旧信不会再浮上来，而两边的身份和额度都还在——**不用重新注册**。

## 6. 种子瓶（海边邮局）

内测期池子太空，第一封信可能捞不到。种子瓶是**你手写的一组信**，在真人信不够时补位；来源固定标注为「海边邮局」，**不伪装成任何一个人**。

- 正文在 `seeds/*.json`（git 管理），谁见过哪封只在 `seeds_used` 表里——所以**海啸淹不掉状态**：重启后正文从文件回来，一封都不会重复，也不会凭空多出来。
- **真人信永远优先**，种子只兜底；**每人最多捞到 2 封**（`BOTTLE_SEEDS_PER_USER_MAX`）；种子照常消耗捞取配额。
- **同一封种子可以被所有人捞到**，但同一个人最多一次。所以 8–12 封能服务任意多人。
- **它不回信**：页面和卡片会写明，也不给「回信」按钮——留一个点了石沉大海的按钮等于骗人类。
- **改完不用重启**：`fs.watch` + 30 秒轮询热载；坏文件跳过并保留上一版。重启会海啸，所以这一条是硬要求。

`seeds/README.md` 是格式说明，`deploy/` 里是 systemd unit（含每 5 分钟 `git pull` 的 timer）。同步用私有 git，**不用 rsync**。

```bash
curl -s http://127.0.0.1:8787/health | jq '{startedAt, seeds}'
# generation 变了 = 热载成功；startedAt 没变 = 进程没重启
```

## 7. 边界

**模型能做的**：起草、捞、在授权范围内读那一封、起草回信、看信箱目录。
**模型不能做的**：发送、读没被授权的信、改人类写的东西、把正文留在工具回执里。

`bottle_catch` 的回执长这样：

```
捞到一封，来自 海盐大福#4821。今天还能寄 2 封，还能捞 3 次。
（正文在人类的信箱页上，你看不到。）
```

**软提示只在卡片和页面上**：命中电话/邮箱/微信号，或本机路径/计算机名/用户名时，多一行提示，主按钮变成「仍然寄出」，照常能寄。服务端**完全不扫正文**——内容已经过人类一遍，一刀切会把「想交个朋友」切成 bug。

## 8. 本地文件与明文

都在 `ctx.dataDir` 下，文件名以 `bottle-` 开头（这个目录 Core 和所有 World 共用）：

| 文件 | 内容 | 明文？ |
|---|---|---|
| `bottle-id.json` | `clientId` 与化名；token 走部署 `.env` | 是（token 不在里面） |
| `bottle-draft.json` | 当前草稿（单人单份，后稿覆盖前稿） | **是，正文** |
| `bottle-letterbook.json` | 手里那封信、收到的回信、写出的信、捞到过的信 | **是，正文** |
| `bottle-card.json` | 当前卡片要显示的那一份数据，每次覆盖 | **是，正文** |

- 这几份都是**环境状态**，不是人格记忆：丢了最多是这封信没了，不会改变它是谁。
- 明文是刻意的：人类要能直接看、直接备份。页面底部会写出账本路径；每条记录可以单独删（带确认），也可以「清空这些记录」（只清历史）。
- 高级模式 → World 页 → 数据页签里也有「本机信件」，可以整份清空；身份与服务端记录不动。
- 服务端只留计数，正文不落盘。

## 9. 已知边界（这一版没做到的）

设计稿 §4.1 要求「人类点回信的那一轮，只给 `bottle_reply`，不给其他任何工具」。**这一版的工具表做不到按轮收窄**：Cortico 的工具表跟着 system 前缀走，一个 session 里是固定的，换表要等上下文交接（`loop.ts` 的 `bindWorlds` 只在 session 新建、交接、清空、前缀重载时跑）。按轮改 `tools()` 会让表在交接时卡在「只剩一个工具」的状态，比不隔离更危险。

所以隔离落在**回执**上：

- 读信期间 `bottle_write` / `bottle_catch` / `bottle_mailbox` 一律返回「这一轮只写回信：用 bottle_reply」，什么都不做；
- `bottle_reply` 只在授权期内可用，没有授权一律回绝；
- 授权一次一条，`onTurnEnded` 收回；
- 真正的兜底是**人**：模型无论被信里的话怎么拐，都寄不出去——发送只在卡片或页面上。

另外：

- **上下文里同时只有一封陌生信**：同时只授权一封；但已经读过的信仍留在 session 历史里，这个删不掉。
- **服务端重启**会带走还在漂的信的正文（海啸）。这是设计，不是 bug。
- **卡片只在 Windows 上**；其它平台自动退回网页。`surface: card` 时如果 PowerShell 被策略拦住，也会退回网页（日志里记一笔）。
